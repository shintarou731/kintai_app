# キンタイ帳（勤務管理アプリ） 製品仕様書

## 概要

- **目的（一文）**：小〜中規模のチーム（数名〜数十名）が、出退勤の打刻・シフト・休暇・修正申請と承認・月次集計を、紙や表計算ソフトに頼らず1つのWebアプリで完結できるようにする。
- **想定ユーザー**
  - **従業員**：毎日出勤・退勤・休憩を打刻し、自分の勤務時間やシフト、休暇の残日数を確認したい人。打刻漏れや休暇は申請で対応したい。
  - **管理者**：チームの勤怠を把握・承認し、シフトを組み、月末に勤務時間を集計して給与計算などに渡したい人（店長・総務担当・チームリーダーなど）。
- **体験のゴール**
  - 従業員は、ログイン後のホーム画面からワンクリックで打刻でき、今月の勤務時間・残業時間・有給残日数がひと目で分かる。
  - 打刻漏れや休暇は申請フォームから出し、承認結果がアプリ内で通知される。
  - 管理者は「今日誰が出勤しているか」「承認待ちが何件あるか」をダッシュボードで即座に把握でき、シフトを週単位で組み、月末には集計を確定（締め）してCSVで書き出せる。

### 前提

- このリポジトリは Rails アプリ（`rails new` 直後の状態）であり、その上に構築する。
- 画面の表示言語は日本語。日時は日本時間（JST）で扱う。
- 1つの組織（会社・店舗）での利用を想定する（複数組織の切り替えは扱わない）。

## 用語

| 用語 | 意味 |
|---|---|
| 打刻 | 出勤・退勤・休憩開始・休憩終了の時刻を記録すること |
| 勤務日 | 出勤打刻をした日。日付をまたいで退勤した場合も、出勤した日の勤務として扱う |
| 実働時間 | 出勤〜退勤の時間から休憩時間を差し引いた時間 |
| 所定労働時間 | 1日あたりの標準の労働時間（勤務ルール設定で決める。初期値 8時間） |
| 残業時間 | その日の実働時間のうち、所定労働時間を超えた部分 |
| 深夜時間 | 22:00〜翌5:00 の間に働いた時間 |
| 休日 | 土曜・日曜と、日本の国民の祝日（振替休日・国民の休日を含む）。祝日はアプリが自動で判定し、表示でも計算でも土日と同じ「休日」として扱う |
| 締め | 管理者がある月の勤怠を確定させ、以後変更できない状態にすること |

## デザインの方向性

- **雰囲気・トーン**：清潔感のある業務アプリ。白〜淡いグレーを基調に、アクセントカラーは落ち着いた青緑（ティール）1色。状態は色で区別する（勤務中＝緑、休憩中＝黄、未出勤・退勤済み＝グレー、却下・アラート＝赤）。装飾は控えめで、数字（時刻・時間）は大きく読みやすく。
- **画面全体の構成のイメージ**
  - 上部に固定ヘッダー：アプリ名、ナビゲーション、未読通知の件数バッジ、ログイン中のユーザー名とログアウト。
  - 従業員のナビ：ホーム（打刻）／勤怠履歴／シフト／申請／休暇。
  - 管理者のナビ：上記に加えて「管理」メニュー（ダッシュボード／承認／従業員／シフト作成／月次集計／設定）。
  - ホーム画面の中央には現在時刻を大きく表示し、その下に状態に応じた打刻ボタンを大きく配置する。
  - 一覧は表形式。スマートフォン幅（375px程度）でも横スクロールなしで打刻・閲覧ができる（表は縦積みのカード表示などに切り替わってよい）。
  - 操作の結果（成功・エラー）は画面上部のメッセージで必ず知らせる。

## 機能一覧

### F1. 初期セットアップとログイン

- ユーザーストーリー：最初の管理者として、アプリを使い始めるために、初回に自分の管理者アカウントを作成し、以後はメールアドレスとパスワードでログインしたい。
- 受け入れ基準
  - [ ] ユーザーが1人も存在しない状態でアプリにアクセスすると、「初期セットアップ」画面（氏名・メールアドレス・パスワード・パスワード確認）が表示される。
  - [ ] 初期セットアップを完了すると、そのユーザーは管理者としてログイン済みになり、ホーム画面に遷移する。
  - [ ] ユーザーが1人以上存在する場合、初期セットアップ画面にアクセスしてもログイン画面へ移動し、新たな管理者は作成できない。
  - [ ] ログインしていない状態でホーム画面など任意の画面にアクセスすると、ログイン画面に移動する。
  - [ ] 正しいメールアドレスとパスワードでログインでき、誤っている場合は「メールアドレスまたはパスワードが正しくありません」という趣旨のエラーが表示される（どちらが誤っているかは明かさない）。
  - [ ] パスワードは8文字以上でなければ登録できず、エラーメッセージが表示される。
  - [ ] ヘッダーのログアウトでログアウトでき、ログイン画面に戻る。
  - [ ] ログイン後のヘッダーにログイン中のユーザー名が表示される。

### F2. 従業員管理（管理者）

- ユーザーストーリー：管理者として、チームのメンバーにアプリを使ってもらうために、従業員アカウントを登録・編集・無効化したい。
- 受け入れ基準
  - [ ] 管理者は「従業員」画面で、従業員の一覧（氏名・メールアドレス・役割・雇用区分・状態）を見られる。
  - [ ] 管理者は氏名・メールアドレス・初期パスワード・役割（従業員／管理者）・雇用区分（正社員／パート・アルバイト）・入社日を入力して従業員を追加できる。
  - [ ] 既に登録済みのメールアドレスでは追加できず、エラーが表示される。必須項目が空でも追加できない。
  - [ ] 管理者は従業員の情報（役割を含む）を編集でき、パスワードを再設定できる。
  - [ ] 管理者は従業員を「無効」にでき、無効になった従業員はログインできない（ログイン時にエラーが表示される）。無効から「有効」に戻すこともできる。
  - [ ] 管理者は自分自身を無効化したり、自分の役割を従業員に変更したりできない（最後の管理者がいなくなるのを防ぐ）。
  - [ ] 役割が「従業員」のユーザーは管理メニューが表示されず、管理画面のURLに直接アクセスしても拒否される（ホームに戻され、権限がない旨が表示される）。
  - [ ] すべてのユーザーは自分のパスワードを変更できる（現在のパスワードの入力が必要）。

### F3. 出勤・退勤の打刻

- ユーザーストーリー：従業員として、自分の勤務時間を正確に記録するために、ホーム画面のボタン1つで出勤・退勤を打刻したい。
- 受け入れ基準
  - [ ] ホーム画面に現在の日付と時刻（秒まで、リアルタイムで進む）が大きく表示される。
  - [ ] 未出勤の状態では「出勤」ボタンだけが押せる。押すとその時刻が出勤時刻として記録され、状態表示が「勤務中」に変わる。
  - [ ] 勤務中の状態では「退勤」ボタンが押せる。押すと退勤時刻が記録され、状態が「退勤済み」になる。
  - [ ] ホーム画面に今日の出勤時刻・退勤時刻・実働時間が表示される。
  - [ ] 退勤済みの日に再度「出勤」を押すことはできない（同じ日に2回出勤打刻はできない。ボタンが無効になるか、押してもエラーになる）。
  - [ ] 日付をまたいで勤務した場合（例：22:00出勤、翌2:00退勤）でも、翌日のホーム画面で「退勤」ボタンが押せ、出勤した日の勤務として記録される。
  - [ ] ブラウザの二重クリックや再読み込みで、同じ打刻が二重に記録されない。
  - [ ] 打刻が成功すると「出勤しました（09:02）」のように時刻入りのメッセージが表示される。

### F4. 休憩の打刻

- ユーザーストーリー：従業員として、実働時間を正しく計算してもらうために、休憩の開始と終了を打刻したい。
- 受け入れ基準
  - [ ] 勤務中の状態では「休憩開始」ボタンが押せ、押すと状態が「休憩中」になる。
  - [ ] 休憩中の状態では「休憩終了」ボタンだけが押せ（退勤は押せない）、押すと「勤務中」に戻る。
  - [ ] 1日に複数回の休憩を記録でき、ホーム画面に今日の休憩合計時間が表示される。
  - [ ] 実働時間は「退勤−出勤−休憩合計」で計算され、ホーム画面・履歴に反映される。
  - [ ] 未出勤・退勤済みの状態では休憩ボタンは押せない。

### F5. 自分の勤怠履歴（月次）

- ユーザーストーリー：従業員として、自分の働きぶりを振り返り給与の見込みを確認するために、月ごとの勤怠記録と合計時間を見たい。
- 受け入れ基準
  - [ ] 「勤怠履歴」画面で、選択した月の1日〜末日までが1行ずつ並び、各日の出勤・退勤・休憩・実働時間・残業時間が表示される。勤務の無い日も空欄の行として表示される。
  - [ ] 休日（土日・祝日）の行は色で区別される。日曜と祝日の行は赤で示し、祝日ではない土曜の行は、日曜・祝日と見分けられる色で示す。
  - [ ] 祝日の行には祝日名（例：「勤労感謝の日」）が表示される。振替休日・国民の休日もそれぞれ「振替休日」「国民の休日」と表示される。
  - [ ] 土曜が祝日の場合も、その行は祝日として赤で示され、祝日名が表示される。
  - [ ] 例：2026年11月の勤怠履歴では、11月23日（月）の行が「勤労感謝の日」として赤く表示される。
  - [ ] 前月・翌月へ移動でき、初期表示は今月である。
  - [ ] 画面上部に、その月の出勤日数・総実働時間・総残業時間・深夜時間の合計が表示される。
  - [ ] 時間は「7:45」（時:分）のように表示され、合計も正しく計算される（例：7:30 と 8:45 の合計は 16:15）。
  - [ ] 退勤打刻が無いまま日付が過ぎた過去の勤務日は「退勤漏れ」として目立つ表示（赤い印など）になる。

### F6. 勤務ルール設定（管理者）

- ユーザーストーリー：管理者として、自社のルールに合った残業計算や集計をするために、所定労働時間や締め日などの勤務ルールを設定したい。
- 受け入れ基準
  - [ ] 管理者は「設定」画面で、1日の所定労働時間（初期値 8:00）、標準の休憩時間（初期値 1:00）、月の締め日（月末／15日／20日／25日から選択、初期値は月末）、月の残業時間の警告ライン（初期値 45時間）を変更・保存できる。
  - [ ] 所定労働時間を変更すると、勤怠履歴の残業時間の表示がそれに従って変わる（例：所定7:00にすると、実働8:00の日の残業は1:00）。
  - [ ] 締め日を変更すると、勤怠履歴・月次集計の「1か月」の範囲がそれに従う（例：20日締めなら「11月度」は10/21〜11/20）。
  - [ ] 不正な値（負の時間、24時間を超える所定労働時間など）は保存できず、エラーが表示される。
  - [ ] 従業員ロールのユーザーは設定画面にアクセスできない。
  - [ ] 勤怠履歴（F5）の総残業時間の下に、現在の警告ラインが「警告ライン 45時間」のように表示される（設定を変えるとその値に変わる）。
  - [ ] その月度の総残業時間が警告ラインを超えたときだけ、「警告ライン（45時間）を超えています」という趣旨の赤字の警告が表示される。ちょうど警告ラインと同じ値（例：45:00）のときは超えていない扱いで警告は出ず、45:01 になると出る。

### F7. 打刻修正申請

- ユーザーストーリー：従業員として、打刻を忘れたり押し間違えたりしたときに正しい記録にするため、修正を申請したい。
- 受け入れ基準
  - [ ] 勤怠履歴の各日の行から「修正申請」を開き、その日の出勤・退勤・休憩（開始・終了、複数可）の正しい時刻と理由を入力して申請できる。打刻が全く無い日についても申請できる。
  - [ ] 理由は必須で、退勤が出勤より前になる等の矛盾した時刻は申請できずエラーが表示される。
  - [ ] 申請すると状態が「承認待ち」になり、「申請」画面の一覧（申請日・対象日・種類・状態）に表示される。
  - [ ] 承認待ちの日は勤怠履歴で「申請中」の印が付く。承認されるまで勤怠記録は変わらない。
  - [ ] 承認待ちの申請は本人が取り下げられる。承認・却下済みの申請は取り下げられない。
  - [ ] 同じ日に対して承認待ちの修正申請を重複して出すことはできない。
  - [ ] 未来の日付に対しては申請できない。

### F8. 承認（管理者）

- ユーザーストーリー：管理者として、勤怠記録の正確さを保つために、従業員から届いた申請を内容を確認して承認・却下したい。
- 受け入れ基準
  - [ ] 管理者は「承認」画面で、承認待ちの申請一覧（申請者・種類・対象日・申請日）を見られ、ナビの「承認」に承認待ち件数のバッジが表示される。
  - [ ] 打刻修正申請の詳細では、現在の記録と申請内容が並べて表示され、変更される箇所が分かる。
  - [ ] 管理者は申請を承認でき、承認すると申請内容どおりに勤怠記録が更新される（従業員の勤怠履歴に反映される）。
  - [ ] 管理者はコメント（却下時は必須）を付けて申請を却下でき、却下しても勤怠記録は変わらない。
  - [ ] 承認・却下の結果とコメントは、申請者の「申請」画面に表示される。
  - [ ] 「承認待ち」「処理済み」で一覧を切り替えられ、処理済みには処理した管理者と日時が表示される。
  - [ ] 自己承認の可否は「有効な管理者」の人数で決まる。「有効な管理者」とは、役割が「管理者」で、かつ状態が「有効」（F2 で無効化されていない）のユーザーを指す。役割が従業員のユーザーや、無効化された管理者は人数に含めない。
  - [ ] 有効な管理者が2人以上いる場合、管理者は自分自身の申請を承認・却下できない。自分の申請の詳細画面には承認・却下の操作が表示されず（または押せず）、「ご自身の申請は他の管理者が処理します」という趣旨の表示が出る。URLを直接操作して承認・却下しようとしても拒否され、申請は「承認待ち」のまま変わらない。
  - [ ] 有効な管理者が1人だけの場合、その管理者は自分自身の申請も承認・却下できる（他の申請と同じ操作・同じ結果になる）。
  - [ ] 有効な管理者が1人だけで自分の申請を開いたとき、詳細画面に「管理者が1名のため、ご自身の申請を承認・却下できます」という趣旨の表示が出て、自己承認・自己却下できる状態であることが分かる。
  - [ ] 管理者の追加・無効化などで有効な管理者の人数が変わると、上記の動作と表示もそれに従って切り替わる（例：管理者が1人の状態から2人目の有効な管理者を追加すると、1人目は自分の申請を承認・却下できなくなる）。
  - [ ] 自己承認・自己却下した場合も、他の申請と同様に処理した管理者として本人の氏名と処理日時が記録され、「処理済み」一覧と申請者の「申請」画面に表示される。

### F9. 休暇申請

- ユーザーストーリー：従業員として、休みを取るために、休暇の種類と日付を指定して申請したい。
- 受け入れ基準
  - [ ] 「休暇」画面から、休暇の種類（有給休暇／特別休暇／欠勤）、期間（開始日〜終了日）、全日・午前半休・午後半休の区分、理由を入力して申請できる。半休は1日のみ指定できる。
  - [ ] 終了日が開始日より前などの不正な期間は申請できない。
  - [ ] 休暇の日数は、期間のうち休日（土日・祝日）を除いて数え（全日1日、半休0.5日）、申請画面・申請一覧・休暇の詳細などで日数を表示する箇所はすべてこの数え方に従う。休日を除いて数えていることが画面上の表示で分かる（例：2026年11月20日（金）〜11月24日（火）の全日の休暇は、11/21（土）・11/22（日）・11/23（勤労感謝の日）を除いて「2日」と表示される）。
  - [ ] 有給休暇は、期間がすべて休日（土日・祝日）で日数が0日になる場合は申請できず、エラーが表示される（例：2026年11月21日（土）〜11月23日（月・勤労感謝の日）の有給休暇は申請できない）。
  - [ ] 既に承認済みまたは承認待ちの休暇と期間が重なる申請はできない。
  - [ ] 休暇申請は F8 の「承認」画面に表示され、管理者が承認・却下できる。
  - [ ] 承認された休暇は、本人の勤怠履歴の該当日に「有給（全日）」「午前半休」のように表示される。
  - [ ] 承認待ちの休暇は本人が取り下げられる。
  - [ ] 未来の日付の承認済み休暇は、本人が「取消申請」を出すことができ、管理者の承認で取り消される。
  - [ ] 従業員が「取消申請」を出せるのは、今のとおり開始日が明日以降の承認済み休暇だけである。開始日が当日または過去の承認済み休暇には取消申請の操作が表示されず、「取消は管理者に依頼してください」という趣旨の案内が表示される。
  - [ ] 管理者は、承認済みの休暇（開始日が当日・過去・未来のいずれでも）を、休暇の詳細画面から理由を入力して直接取り消せる。取消申請や承認の手続きは不要で、操作した時点で取り消される。理由が空の場合は取り消せず、エラーが表示される。
  - [ ] 管理者が直接取り消すと、取り消した管理者の氏名・日時・理由が記録され、その休暇の詳細画面と「承認」画面の処理済み一覧で確認できる。本人の勤怠履歴（F5）の該当日からは休暇の表示が消える。有給休暇の場合、F10 の実装後は残日数が取り消した日数分だけ戻る。
  - [ ] 承認待ちの取消申請がある休暇を管理者が直接取り消した場合、その取消申請は承認待ち一覧から消え、休暇が取り消し済みであることが分かる表示になる（同じ休暇が二重に取り消し処理されない）。
  - [ ] 管理者が自分自身の休暇を直接取り消す場合は、F8 の自己承認ルールと同じ扱いにする。有効な管理者が2人以上いれば自分の休暇は直接取り消せず、「ご自身の休暇は他の管理者が取り消します」という趣旨の表示が出る。有効な管理者が1人だけなら直接取り消すことができ、「管理者が1名のため、ご自身の休暇を取り消せます」という趣旨の表示が出る。
  - [ ] 締め済み（F14）の月度に1日でもかかる休暇は、管理者でも直接取り消せない（操作が表示されないか、実行するとエラーになり、休暇は承認済みのまま変わらない）。
  - [ ] 従業員ロールのユーザーは、URL を直接開いたりフォームを直接送信したりしても、休暇を直接取り消せない（拒否され、休暇は承認済みのまま変わらない）。

### F10. 有給休暇の残日数管理

- ユーザーストーリー：従業員として、休暇を計画的に取るために、有給休暇の残日数を知りたい。管理者として、法令に沿って有給を付与し取得状況を把握したい。
- 受け入れ基準
  - [ ] 管理者は従業員ごとに有給休暇を付与（付与日・日数・有効期限）できる。有効期限の初期値は付与日から2年後。
  - [ ] 従業員の「休暇」画面とホーム画面に、有給の残日数（0.5日単位、例：「残り 7.5日」）が表示される。
  - [ ] 有給休暇の申請が承認されると残日数が減り（全日1日、半休0.5日、休日（土日・祝日）は日数に数えない）、取り消されると戻る。
  - [ ] 残日数を超える有給休暇は申請できず、エラーが表示される（承認待ちの申請分も考慮する）。
  - [ ] 有効期限が切れた付与分は残日数から除かれ、古い付与分から先に消化される。
  - [ ] 「休暇」画面に付与・取得の履歴（日付・日数・種類）が表示される。
  - [ ] 管理者は従業員一覧で各従業員の有給残日数と、当年度（4月1日〜翌年3月31日）の取得日数を確認できる。当年度の取得日数が年5日未満の従業員には印が付く。ただし、有給の付与が無い従業員には印を付けない。
  - [ ] 「有給の付与が無い」とは、当年度と使える期間（付与日〜有効期限）が1日も重ならない付与しか無いこと（付与が1件も無い場合を含む）をいう。削除した付与（下記）は数えない。役割（従業員／管理者）にかかわらず同じ基準で判定する。
  - [ ] 例：当年度が 2026/04/01〜2027/03/31 のとき、付与が1件も無い従業員と、付与日 2024/03/01・有効期限 2026/02/28 の付与だけを持つ従業員には、当年度の取得が0日でも印が付かない。付与日 2026/10/01 に10日付与され当年度の取得が2日の従業員には印が付く。当年度中に有効期限が切れた付与（例：有効期限 2026/06/30）だけを持つ従業員も「付与がある」ものとして扱い、当年度の取得が5日未満なら印が付く。
  - [ ] 管理者は誤って登録した付与を削除できる。削除するときは理由の入力が必須で、理由が空の場合は削除できずエラーが表示され、付与はそのまま残る。
  - [ ] 付与を削除すると、削除した管理者の氏名・削除日時・理由と、削除した付与の内容（付与日・日数・有効期限）が記録される。この記録は、その従業員の付与・取得の履歴（管理者が見る従業員ごとの付与の画面と、本人の「休暇」画面の履歴）に「付与の削除」と分かる形で表示される。
  - [ ] 削除した付与は、残日数・申請できる残日数の計算に使われない（例：残り 10日の従業員から、まだ使っていない 10日の付与を削除すると「残り 0日」になる）。
  - [ ] 削除すると承認済み・承認待ちの有給休暇が残日数で賄えなくなる場合は削除できず、その理由が表示される。この場合、付与はそのまま残り、削除の記録も作られない。

### F11. シフト作成（管理者）

- ユーザーストーリー：管理者として、必要な人員を配置するために、週単位でメンバーのシフト（勤務予定）を作成・公開したい。
- 受け入れ基準
  - [ ] 管理者は「シフト作成」画面で、縦に従業員・横に1週間（月〜日）の表を見られ、前週・翌週に移動できる。
  - [ ] 表の日付の列見出しでは、祝日を日曜と同じ赤で示し、祝日名（例：「勤労感謝の日」）を表示する。
  - [ ] 表のマスを選び、開始時刻・終了時刻・休憩時間を入力してシフトを登録・変更・削除できる。日付をまたぐシフト（例：22:00〜翌6:00）も登録できる。
  - [ ] よく使う時間帯を「シフトパターン」（例：早番 9:00〜18:00、遅番 13:00〜22:00）として登録し、マスに素早く割り当てられる。
  - [ ] 前の週のシフトを今の週にまとめてコピーできる（既にシフトがあるマスは上書きしない、または確認する）。
  - [ ] 各日の列に、その日のシフト人数が表示される。
  - [ ] 承認済み休暇の日のマスには「休暇」と表示され、そこにシフトを入れようとすると警告が出る。
  - [ ] シフトは「下書き」と「公開」の状態を持ち、管理者が週単位で「公開」するまで従業員には見えない。公開後に変更した場合は変更があったことが分かる。

### F12. シフト確認と予実比較

- ユーザーストーリー：従業員として、いつ働くか把握するために自分のシフトを確認したい。管理者として、シフトどおりに勤務されたかを確認したい。
- 受け入れ基準
  - [ ] 従業員は「シフト」画面で、自分の公開済みシフトを月のカレンダー形式で見られる（日付ごとに時間帯が表示される）。
  - [ ] 「シフト」画面のカレンダーでは、祝日を日曜と同じ赤で示し、祝日名（例：「勤労感謝の日」）を表示する。
  - [ ] ホーム画面に今日と次回のシフト（例：「今日 9:00〜18:00」「次回 11/26 13:00〜22:00」）が表示される。
  - [ ] 勤怠履歴の各日に予定（シフト）と実績（打刻）が並べて表示される。
  - [ ] シフト開始時刻より後に出勤した日は「遅刻」、シフト終了時刻より前に退勤した日は「早退」、シフトがあるのに打刻も休暇も無い過去の日は「欠勤」の印が付く（許容範囲は1分。例：9:00開始で9:01出勤は遅刻にならない、9:02は遅刻）。
  - [ ] 管理者は従業員ごと・月ごとの遅刻・早退・欠勤の回数を確認できる。

### F13. 管理者ダッシュボード（今日の出勤状況）

- ユーザーストーリー：管理者として、現場の状況をすぐ把握するために、今日の全員の勤務状況と対応が必要な事項を1画面で見たい。
- 受け入れ基準
  - [ ] 管理者の「ダッシュボード」に、有効な従業員全員の今日の状態（勤務中／休憩中／退勤済み／未出勤／休暇）と、出勤時刻・シフトが一覧表示される。
  - [ ] 状態ごとの人数（例：勤務中 5名、未出勤 2名）が上部にまとめて表示される。
  - [ ] シフトの開始時刻を過ぎても出勤していない従業員は「未出勤（遅れ）」として赤く強調される。
  - [ ] 承認待ちの申請件数と、前日以前の退勤漏れ件数が表示され、それぞれの一覧画面へ移動できる。
  - [ ] 今月の残業時間が警告ライン（F6）の80%を超えている従業員が一覧で表示される。
  - [ ] 画面を再読み込みすると最新の状態が反映される。

### F14. 月次集計と締め（管理者）

- ユーザーストーリー：管理者として、給与計算に使う正しい数字を確定させるために、月ごとに全員の勤怠を集計し、確認後に締めたい。
- 受け入れ基準
  - [ ] 管理者は「月次集計」画面で、選択した月度（F6 の締め日に従う）の全従業員の出勤日数・総実働時間・残業時間・深夜時間・休日（土日・祝日）勤務時間・有給取得日数・遅刻/早退/欠勤回数を表で見られる。
  - [ ] 従業員の行から、その従業員のその月の日別勤怠（F5 と同等の表）を開ける。管理者はそこから勤怠記録を直接修正でき、修正には理由の入力が必須で、修正履歴（誰が・いつ・何を・なぜ）が残り閲覧できる。
  - [ ] 退勤漏れや承認待ちの申請が残っている月は、警告として件数が表示される。
  - [ ] 管理者は月度を「締め」られる。締める前に確認ダイアログが表示される。
  - [ ] 締めた月度の勤怠は、打刻修正申請・休暇申請・管理者の直接修正・管理者による休暇の直接取消（F9）のいずれでも変更できない（申請画面で締め済みの日は選べない、またはエラーになる。締め済みの月度にかかる休暇は取消の操作ができない、またはエラーになる）。
  - [ ] 管理者は締めを解除でき、解除した記録（誰が・いつ）が残る。
  - [ ] 一覧上で各月度が「未締め」「締め済み」のどちらかが分かる。
  - [ ] 締めた月度の集計値（出勤日数・総実働時間・残業時間・深夜時間・休日（土日・祝日）勤務時間・有給取得日数・遅刻/早退/欠勤回数）と日別の値（実働・残業・深夜など）は、締めた時点の勤務ルールで計算した値に固定される。締めた後に勤務ルール（所定労働時間・標準の休憩時間・締め日など）を変更しても、締め済み月度の月次集計画面・日別勤怠の表示も、CSV（F15）の内容も変わらない（例：所定8:00で締めた月度は、締め後に所定7:00へ変更しても、実働8:00の日の残業は0:00のまま）。
  - [ ] 締め日を変更しても、締め済み月度の期間（開始日〜終了日）は締めた時点のまま変わらない。月次集計画面と勤怠履歴には、表示中の月度の期間（開始日〜終了日）が表示され、これを確認できる。
  - [ ] 締め日の変更によって締め済み月度と未締めの月度の期間が重なったり、すき間が空いたりする場合、未締めの月度の期間は次のように決まる。どの日も必ずちょうど1つの月度に含まれ、重複や抜けが出ない。
    - 直前の月度が締め済みの場合、未締め月度の開始日は「締め済み月度の終了日の翌日」とする（例：20日締めで「11月度（10/21〜11/20）」を締めた後に月末締めへ変えると、「12月度」は 11/21〜12/31 になる。15日締めへ変えた場合は 11/21〜12/15 になる）。
    - 直後の月度が締め済みの場合、未締め月度の終了日は「締め済み月度の開始日の前日」とする。
    - それ以外の端は、現在の締め日に従う。
  - [ ] 締めを解除すると、その月度の期間と値は現在の勤務ルールで計算し直される（期間は上記の重なり・すき間の扱いに従う）。もう一度締めると、その時点の勤務ルールで計算した値で改めて固定される。
  - [ ] 従業員の勤怠履歴（F5）でも、締め済み月度は固定された値（期間・日別の値・合計）で表示され、締め後に勤務ルールを変更しても表示は変わらない。

### F15. CSVエクスポート（管理者）

- ユーザーストーリー：管理者として、給与計算ソフトや表計算ソフトで使うために、勤怠データをCSVで書き出したい。
- 受け入れ基準
  - [ ] 月次集計画面から、その月度の従業員別集計（F14 の表の項目）をCSVでダウンロードできる。
  - [ ] 月次集計画面から、その月度の全従業員の日別明細（従業員名・日付・出勤・退勤・休憩・実働・残業・深夜・休暇・遅刻/早退/欠勤）をCSVでダウンロードできる。
  - [ ] CSVはExcelで開いても日本語が文字化けしない。
  - [ ] ファイル名に月度が含まれる（例：「勤怠集計_2026年11月度.csv」のように内容が分かる名前）。
  - [ ] CSVの数値は画面の表示と一致する。
  - [ ] 従業員ロールのユーザーはCSVをダウンロードできない。

### F16. アプリ内通知

- ユーザーストーリー：従業員・管理者として、対応や確認が必要な出来事を見逃さないために、アプリ内で通知を受け取りたい。
- 受け入れ基準
  - [ ] ヘッダーにベルアイコンと未読件数のバッジが表示され、クリックすると通知一覧が開く。
  - [ ] 従業員は、自分の申請が承認・却下されたとき、自分のシフトが公開・変更されたとき、有給が付与されたときに通知を受け取る。
  - [ ] 管理者は、新しい申請が届いたときに通知を受け取る。
  - [ ] 従業員は、今月の残業時間が警告ライン（F6）の80%および100%を超えたときに、それぞれ1回ずつ通知を受け取る（管理者にも同時に通知される）。
  - [ ] 通知をクリックすると関連する画面（申請の詳細・シフトなど）に移動し、その通知は既読になる。「すべて既読にする」もできる。
  - [ ] 通知一覧は新しい順に並び、通知の発生日時が表示される。

## スコープ外

- 給与計算そのもの（時給・手当・控除などの金額計算）
- 複数の組織・店舗・部署の管理と、部署ごとの承認者設定（承認は管理者ロールなら誰でも行える）
- 会社独自の休日（創立記念日・夏季休業・年末年始休業など）の登録・管理、および管理者が祝日を登録・編集する機能（休日は土日と日本の国民の祝日だけで、アプリが自動で判定する）
- 変形労働時間制・フレックスタイム制・裁量労働制など特殊な労働時間制度への対応
- 打刻時刻の丸め（15分単位切り捨てなど）
- 位置情報（GPS）・IP制限・顔認証・ICカードによる打刻
- メール・チャット（Slack 等）・プッシュ通知などアプリ外への通知
- 従業員の自己登録（アカウントは管理者が作成する）、パスワードを忘れた場合のメールによる再設定
- 外部の給与・人事システムとのAPI連携（CSV出力のみ対応）
- 有給休暇の法定日数（勤続年数に応じた日数）の自動付与（付与は管理者が手動で行う）
- 多言語対応・タイムゾーンの切り替え
