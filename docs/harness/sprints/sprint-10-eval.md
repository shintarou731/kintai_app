   - 実際の動作：状態の欄で、バッジが登録者・メモと横に並び、高さいっぱいに伸びる（スクリーンショット `s10-grants-history-375.png`）。履歴のリンク「有給休暇・全日（5日）」は3〜4行に折り返す。
2. **[軽微] 承認待ちの申請があると、誤って登録した付与を削除できないことがある**
   - double に3日を付与した状態で、承認待ちの ID 25（5日）があると、その3日の付与は削除できなかった。メッセージは「…3日 が付与で賄えなくなるため、削除できません」。

3. **[軽微] 日数に "abc" を入れたときのメッセージが「0.5日以上、40日以下にしてください」になる**
   - 数値でないことが伝わりにくい。ただし通常の入力欄（type=number）では起きない。

## generator が決めた扱いへの所見
- **当年度は 4/1〜翌3/31**
  - 仕様に年度の定義は無いので、矛盾しない。
  - 法令上の「年5日」は付与日（基準日）から1年で数えるのが正確だが、会計年度で簡略化するのは小規模な事業所では一般的。一覧に期間を明記しているので、誤解は少ない。
  - 将来、基準日ごとの判定が必要になったら仕様の追加が要る。
- **今後の承認済み有給を「取得予定」として含める**
  - 「年5日を取らせる」という管理の目的には合っている。「（うち予定 3日）」と内訳を出しているので、実績と予定の区別も付く。妥当。
- **付与0件で承認済みの有給があるときは「残り 0日」＋「付与を超えた取得 X日」**
  - マイナスを出さずに不整合を見える化しており、既存データからの移行として使いやすい。遡った付与で不足が消えることも確かめた（hanako の超過 2日 → G1 の付与で解消）。妥当。
- **5日未満の印を全員に付ける**
  - 仕様の文言どおりで、矛盾しない。
  - ただし、付与の無い人（jiro）や管理者自身にも赤い印が付く。実際には対象外の人にも警告が並ぶので、警告に慣れて見落とす恐れがある。
  - 将来は「付与10日以上の人だけ」に絞る選択肢を、オーケストレーター経由で planner に相談するとよい。
- **付与の削除は物理削除**
  - 「誤登録の訂正」に限った操作で、賄えなくなる場合は止まる。訂正用としては許容できる。
  - ただし、誰がいつ削除したかの記録が残らない。F14（締め）以降に監査が必要になるなら、論理削除か操作の記録を検討すべき。
