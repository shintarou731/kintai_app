## 実装内容

### データ（マイグレーション 1 件・適用済み）
`db/migrate/20261125120000_create_paid_leave_grants.rb`
- 新しい表 `paid_leave_grants`（有給の付与）を作るだけ。既存の表と行は変えていない。

  | 列 | 意味 |
  |---|---|
  | `user_id` | 付与された従業員 |
  | `granted_on` | 付与日（この日から使える） |
  | `half_days` | 日数を「0.5日の個数」で持つ整数（10日 → 20、7.5日 → 15）。小数の誤差を出さないため |
  | `expires_on` | 有効期限（この日まで使える。翌日に失効） |
  | `granted_by_id` | 登録した管理者 |
  | `note` | メモ（任意） |

- DB の制約：`half_days > 0`、`expires_on >= granted_on`。
- 適用前に、開発 DB のバックアップを取った：`tmp/backup/development-before-sprint-10.sqlite3`
  - WAL ファイルに未反映の変更があったため、単純なコピーではなく `VACUUM INTO` で、整合した状態を保存した。
  - バックアップの件数を読み取って確かめた（申請 45・勤怠 23）。
- 適用前後の開発 DB は同じ件数：ユーザー 4・勤怠 23・休憩 21・申請 45（承認待ち 5）。付与は 0 件。

### 残日数の計算（保存せず、毎回計算する）
- **`PaidLeaveLedger`（台帳）**：付与と有給休暇から、残日数・不足・付与ごとの使用と残りを計算する。DB は使わない。
  - 休暇の日数は `LeaveRequest#working_dates`（休日＝土日・祝日を除く）× 2単位（全日）または 1単位（半休）。
  - 休暇の日を日付の早い順に処理する。その日に使える付与（付与日 ≦ その日 ≦ 有効期限）のうち、**付与日の古い順**に充てる。
    - 1日分が2つの付与にまたがることもある（0.5日ずつ）。
  - **残日数**＝今日の時点で有効な付与（付与日 ≦ 今日 ≦ 有効期限）の、使っていない日数の合計。
  - どの付与でも賄えない日数は「不足」として別に数える。
- **`PaidLeaveAccount`**：1人分の表示用の値をまとめる。
  - 残り：承認済みの有給だけを引く。
  - 承認待ち、申請できる残り：承認待ちも引く。
  - 不足、次に失効する分、当年度の取得（予定の内訳つき）、5日未満かどうか、履歴。
  - 従業員一覧では `for_users` を使い、全員分の付与と休暇を2回の問い合わせで読む。
- 残日数を DB に持たないので、次のことが、別に書き込む処理なしで成り立つ。
  - 承認すると、休暇が `effective` になって減る。
  - 取り消すと（取消申請の承認・管理者の直接取消のどちらでも `cancelled_at` が入る）、`effective` でなくなって戻る。
  - `LeaveRequest#mark_cancelled!` には、このことを説明するコメントだけを足した。

### 申請・承認での確かめ（`LeaveRequest`）
- **申請時**：`paid_leave_must_fit_balance`
  - 承認済みと承認待ちの他の有給を先に数える。そのうえで、この申請を足すと不足が増えるなら拒否する。
  - 申請者の行のロックと BEGIN IMMEDIATE の中で確かめる（既存の `#submit`）。
  - メッセージの例：「有給休暇の残日数が足りないため申請できません（この申請 3日・休暇の日付に使える残り 2日）」。
    - 承認待ちがあるときは「承認待ちの有給 2日 も差し引いて数えています」を添える。
    - 今の残りは足りるが、休暇の日付には有効期限が切れている場合は、その理由も出す。
- **承認時**：`approval_blockers`
  - 承認済みの有給だけを数えて、確かめ直す。画面（ボタンの無効化と理由の表示）とサーバー（`ApprovalReview` のトランザクションの中）で同じ判断を使う。
  - 足りなければ「有給休暇の残日数が足りないため承認できません（…）。有給を付与してから承認するか、却下してください」と出す。却下はできる。
- **同時実行**：`ApprovalRequest#lock_for_review!` というフックを足した。
  - `ApprovalReview` が申請の行をロックした直後に呼ぶ。`LeaveRequest` では申請者の行をロックする。
  - SQLite は BEGIN IMMEDIATE で直列になる。PostgreSQL などでも、同じ人の申請と承認が入れ違わないようにするため。
- **不足の扱い**：既にある不足（付与の無い時期の有給など）は、新しい申請のせいにしない。比べるのは「この申請で増える不足」だけ。

### 管理者の付与の画面（`/admin/employees/:id/paid_leaves`）
- `Admin::Employees::PaidLeaveGrantsController`（index / create / destroy）。
- 画面の内容：残日数のカード、付与のフォーム、付与の一覧、付与・取得の履歴。
  - 付与の一覧の項目：付与日・日数・有効期限・使用・残り・状態（有効／期限切れ）・登録者・メモ。
- 付与のフォーム
  - 初期値は、付与日＝今日、日数＝10、有効期限＝2年後。
  - 付与日を変えると、有効期限が付与日の2年後に追従する（`grant_form_controller.js`）。有効期限を手で変えた後は追従しない。
  - 有効期限が空欄でも、サーバー側で付与日の2年後にする。
- 入力の確かめ
  - 日数は 0.5日単位で、0.5〜40日。
  - 付与日は、今日から5年前〜今日。未来の日付は不可。
  - 有効期限は付与日以降。
  - 誤りは 422 で返し、上部のメッセージと項目のエラーを出す。
- 削除（`PaidLeaveGrantRemoval`）：誤って登録した付与を取り除く操作。
  - 削除すると承認済み・承認待ちの有給が賄えなくなる場合は、削除できない。
  - 従業員の行をロックしてから確かめる。
- 入口は3か所：従業員一覧の残日数のリンク、従業員の編集画面の「有給休暇」カード、URL。

### 表示
- **休暇画面**：上部に残日数のカードを出す。
  - 「残り 7.5日」・承認待ち・申請できる残り・当年度の取得（うち予定）。
  - 次に失効する日と日数。
  - 不足があれば注意。付与が無いときは、その案内。
  - 下部に、付与・取得の履歴（新しい順）を出す。
    - 種類は、付与（+）／取得（−、どの付与から消化したか）／取得の取消（打ち消し線と「戻し済み」）／失効（−）／申請中（括弧つき。まだ引かない）。
    - 取得と申請中の行は、休暇の詳細にリンクする。
- **ホーム画面**：今日の勤務の下に、「有給休暇 残り 7.5日」の小さなカードを出す。
  - 承認待ち・失効予定・未付与・付与を超えた取得も、ひとこと添える。
- **従業員一覧**：「有給の残り」「当年度の取得」の列を足した。
  - 当年度の取得が5日未満の人には、赤い「5日未満」の印を付ける。
  - 不足がある人には「超過 X日」を出す。
- **休暇の詳細**（本人・承認画面の両方）：「有給の残日数」の行を足した。状態ごとの表示は次のとおり。
  - 承認待ち：「今は 残り 2日。承認されると 0日 になります」。足りなければ、赤で「残日数が足りません」。
  - 承認済み：この休暇を引いた残り。どの付与から消化したか。
  - 取消済み：「取り消したため残日数に戻しました」。
- **メッセージ**
  - 承認したとき：「有給休暇の残日数から2日引きました。」を添える。
  - 取消申請の承認・直接取消のとき：「有給休暇の残日数に2日戻しました。」を添える。
  - 承認画面の説明文も、有給なら残日数への影響を書く。
- **申請画面のプレビュー**：有給休暇を選んでいるときは、申請できる残りと比べる。
  - 超えるとき：赤で「有給休暇の申請できる残り（1.5日）を超えています」。
  - 超えないとき：「申請後の有給の残り 0.5日」。

### スプリント 9.2 の評価の指摘の修正
1. **1年より先の日付のプレビュー**
   - 開始日・終了日が申請できる範囲（今日の前後1年）の外なら、日数を出さない。代わりに「申請できるのは 2025/11/25〜2027/11/25 の日付です。この期間は申請できません。」と出す。
   - 日付の入力欄にも `min`／`max` を付けた。フォームの説明にも範囲を書いた。
2. **休暇の期間内の休日の表示と、数え方をそろえた**
   - 期間内の休日（土日・祝日）の行には、休暇のバッジ（ティールの塗り）を出さない。代わりに、点線の薄いバッジ「休日（有給の期間中）」を出す。承認待ちの場合は「休日（有給の申請期間中）」。
   - その行は、休暇の日の色（`history-row--leave`）にしない。凡例にも追加した。
   - 月の休暇欄では、0日になる種類も「特別休暇 0日」と出す。休日だけの特別休暇で、バッジがあるのに「なし」と出る食い違いがなくなる。
   - 11/20〜11/24 の有給は、ティールのバッジが2日分になり、月の合計「有給 2日」と一致する。
3. **375px で祝日の行に「勤務なし」が出ない**
   - 祝日の行で「勤務なし」を隠していた CSS をやめた。
   - 修正申請の欄が空の日は、日付の欄を行の幅いっぱいに広げる（`:has()`）。
   - 2027/2/11（建国記念の日）でも1行（高さ 50px 未満）に収まることを、システムテストで確かめた。
4. **`holiday_jp` の内部 Hash の参照**
   - `holiday_calendar_test.rb` にテストを足した。2025〜2028年の毎日で、`HolidayJp.holiday?` と `HolidayCalendar.holiday?` が一致することを確かめる。2026〜2027年の祝日名も、公開 API の `HolidayJp.between` と一致することを確かめる。
   - Gemfile は、すでに `~> 0.8.1`（0.8.x だけ）で固定されているので、変えていない。

## 決めた扱い（仕様に書かれていない点）

| 項目 | 決めた扱い |
|---|---|
| 有効期限の意味 | 「この日まで使える」日（その日を含む）。翌日に失効する。初期値は付与日 + 2年（Rails の `2.years`。2/29 の付与は 2/28 まで） |
| 付与分を使える休暇 | 付与日 ≦ 休暇の日 ≦ 有効期限 の日だけ。付与日より前の日・期限の後の日には使えない |
| 消化の順番 | 休暇の日を日付順に処理する。その日に使える付与のうち、付与日の古い順に充てる（同じ日なら有効期限の早い順） |
| 残日数 | 今日の時点で有効な付与の、未使用の日数。未来の日付の休暇も、承認された時点で引く。承認待ちは引かない（「申請できる残り」で引く） |
| 申請できる上限 | 承認済み＋承認待ち＋この申請の全日数を、日付ごとに賄えること。今の残りが足りても、休暇の日付に有効な付与が足りなければ拒否する |
| 付与日 | 今日まで（未来は不可）。5年前まで |
| **付与が0件で、承認済みの有給があるとき** | **残日数はマイナスにせず「残り 0日」と出す。** 超えた分は「付与された日数を超えて取得した有給休暇が 2日 あります」と別に出す（休暇画面・ホーム・付与の画面・従業員一覧の「超過 2日」）。新しい有給は申請できない。承認待ちの有給は承認できない（却下はできる）。管理者が実際の付与日（過去の日付）で付与を登録すると、その時期の有給にも充てて計算し直し、不足は消える |
| **当年度** | **4月1日〜翌年3月31日（日本の会計年度）**。今日（2026-11-25）なら 2026/04/01〜2027/03/31。従業員一覧に期間を明記した |
| 当年度の取得日数 | 当年度の日付に当たる、承認済みで取り消されていない有給の日数（休日を除く・半休は0.5日）。今日より後の分は「取得予定」として内訳に出し、合計と5日の判定に含める。承認待ち・取消済みは数えない。年度をまたぐ休暇は、年度内の日だけを数える |
| 「5日未満」の印 | 当年度の取得（予定を含む）が5日未満の全員に付ける。付与が無い人・無効な人も含む（法令では年10日以上付与された人が対象だが、仕様の文言どおり全員に付けた） |
| 付与の訂正 | 編集機能は作らず、削除と再登録で直す。削除すると承認済み・承認待ちの有給が賄えなくなる場合は削除できない |
| 管理者が自分に付与すること | 制限していない（仕様に記載が無いため） |

## 既知の問題・懸念
- **開発 DB の承認待ちの有給（ID 25・30）は、付与を登録するまで承認できない**。仕様どおりの動きだが、評価の前に付与が必要になる。
- 申請画面のプレビューは、今の「申請できる残り」とだけ比べる。有効期限が休暇の日付より前に切れる場合（日付ごとの判定）は、送信してサーバーが拒否するまで分からない。
- 「5日未満」の印は全員に付く。付与の無い人、10日未満しか付与されていないパートの人、無効な人にも付く（法令上の対象者の判定はしていない）。
- 付与の編集機能は無い（削除して登録し直す）。削除は誤登録を直すためのもので、記録は残らない（物理削除）。
- 承認待ちの有給は、付与の失効の計算に入れていない。承認待ちのまま期限を過ぎると、承認時に「残日数が足りない」と出る。
- 有給休暇でも、月をまたぐ休暇で、その月に入る日が土日だけなら、勤怠履歴の月の休暇欄に「有給 0日」と出る（バッジは休日の表示なので、食い違いはない）。
- 375px の祝日の行の調整に CSS の `:has()` を使った。古いブラウザでは、日付の欄が広がらず、「勤務なし」が2行目に折り返すことがある（表示は崩れない）。
- 日付の入力欄に `max`（今日+1年）を付けたため、範囲外の日付を送ろうとすると、ブラウザが先に止めて、ブラウザ自身のメッセージを出す。サーバー側の確かめは従来どおり。
- 従業員一覧・付与の画面は、表示のたびに全員分の台帳を計算する。数十人なら問題ないが、数百人以上なら集計の保存（キャッシュ）を検討する必要がある。
