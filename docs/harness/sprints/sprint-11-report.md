### データ（マイグレーション 1 件・適用済み）
`db/migrate/20261125150000_create_shifts.rb`。新しい表を3つ作るだけで、既存の表と行は変えていない。

- 適用前に、開発 DB のバックアップを取った：`tmp/backup/development-before-sprint-11.sqlite3`
  - `VACUUM INTO` で保存した（WAL に未反映の分も含めるため）。
  - バックアップを読み取り専用で開き、件数がユーザー 4・勤怠 23・申請 55・付与 5 であることを確かめた。
- 適用後の開発 DB も同じ件数。シフト・パターン・公開の記録は 0 件（開発 DB にデータは入れていない）。

| 表 | 内容 |
|---|---|
| `shift_patterns` | パターン名（一意）・開始・終了・休憩（分） |
| `shifts` | 従業員・日付（work_date）・開始・終了・休憩（下書き）、`published_*`（公開中の内容）、`published_at`、`revised_at`、`removed_at`（削除予定）、`created_by`・`updated_by`、`lock_version` |
| `shift_publications` | 週（月曜日）・公開した人・日時・追加／変更／削除の件数（公開の履歴） |

- 時刻は「その日の 0:00 からの分」（0〜1439）で持つ。終了が開始より前なら、翌日に終わるシフト。
- DB の制約：`(user_id, work_date)` は一意。分は 0〜1439、開始≠終了、休憩は 0 以上。

### モデル
- **`ShiftTimeFields`（concern）**：シフトとパターンで共通の、時刻と休憩の入力と確かめ。
  - 「9:00」「09:00」「９：００」を受け付ける。休憩が空欄なら 0分。
  - 次の場合は拒否する：終了＝開始、休憩が勤務時間以上、数値でない休憩・マイナス・小数、時刻の形の誤り。
- **`Shift`**
  - 状態は `draft`（未公開）／`published`（公開中）／`changed`（公開後に変更・未公開）／`removing`（削除・未公開）。
  - 前日・翌日のシフトと時間が重なる登録は拒否する。日付をまたぐシフトも含めて比べる。
  - 次の登録も拒否する：無効な従業員のシフト、今日から前後1年の範囲外の日付、確認の無い全日の休暇の日。
  - 削除（`remove!`）：一度も公開していなければ、行ごと消す。公開済みなら削除予定にする。
  - `publish_draft!`：下書きを公開する。`lock_version` は変えない。
- **`ShiftBoard`**：1週間分の表示用データ（行・マス・人数・週の実働・週の状態・公開の履歴・コピーの見込み）。
- **`ShiftAssignment`**：パターンの割り当て。画面で見ていたマスの状態（`lock_version`）と違えば、割り当てない。
- **`ShiftWeekCopy`**：前週のコピー（上書きしない）。
- **`ShiftWeekPublication`**：週の公開。その週の行をロックしてから読み直して反映し、公開の記録を残す。
- **`ShiftPattern`**・**`ShiftPublication`**。

### 画面
- **シフト作成**（`/admin/shifts?week=2026-11-23`）。管理メニューに「シフト作成」を足した（従業員と設定の間）。
  - **週の移動**：「← 前週」「翌週 →」「今週」。日付を選んで、その日の週を開くこともできる。開けるのは今日から前後1年。
  - **週の状態**：バッジで出す（シフトなし／下書き（未公開）／公開後の変更あり（未公開）／公開済み）。
    - あわせて、未公開の変更の件数と、最終公開の日時・公開した人を出す。
  - **操作**：「前週をコピー」「この週を公開」。どちらも、件数の見込みを書いた確認のダイアログを出す。公開する変更が無いときは、公開のボタンを押せない。
  - **パターンで割り当て**：パターンを選んでマスを押すと、そのパターンが入る。
    - 割り当てた後は、同じ URL に戻す。Turbo 8 のページの更新（morph）と `scroll-keeper` コントローラで、ページと表の横スクロールの位置を保つ。
  - **シフト表**：縦に有効な従業員、横に月〜日、右端に週の実働の予定。
    - 列見出し：土曜は青。日曜と祝日は赤で、祝日名のチップを出す。今日はティールの線。各日の人数も出す。
    - 表の下に、人数の合計の行がある。
  - **マス**
    - 時刻（「22:00〜翌6:00」）、パターン名と休憩、状態のバッジを出す。
    - 公開後に変更したマスには「公開中 9:00〜18:00」も出す。
    - 承認済みの休暇の日は、「休暇」のバッジと斜線の背景。全日の休暇の日にシフトがあるマスは、赤い枠と「休暇の日のシフト」。半休の日は「午前半休」のバッジ。
  - 無効な従業員の、その週のシフトは、表の下に別の一覧で出す。
  - その週の公開の履歴（最新5件）を出す。
- **シフトの登録・変更**（`/admin/shifts/new?user_id=&date=`、`/admin/shifts/:id/edit`）
  - パターンのボタンを押すと、開始・終了・休憩に入る。
  - 入力に合わせて、勤務時間・実働の予定・日付をまたぐかを表示する（`shift_form_controller.js`）。
  - 公開の状態を説明する。最終更新者も出す。
  - 全日の休暇の日には、警告と確認のチェックボックスを出す。半休の日には注意を出す。
  - 削除のボタン（確認つき）。
- **シフトパターン**（`/admin/shift_patterns`）：一覧・登録・編集・削除。20件まで。

## F12 に向けて用意したもの（F12 の機能は作っていない）
- **公開済みだけを従業員に見せる**
  - `Shift.published` を使う（削除予定も、次の公開までは含む）。
  - 時刻は `published_starts_at`、`published_ends_at`、`published_break_minutes`、`published_scheduled_work_minutes`、`published_range_label` で読む。
  - 下書きの列（`start_minute` など）は、従業員の画面では使わないこと。
- **予定と実績の比較**
  - `published_starts_at` と `published_ends_at` は、JST の Time（日付をまたぐ分も計算済み）。
  - 勤怠（`Attendance` の `work_date`・`clock_in_at`・`clock_out_at`）と、同じ `work_date` で突き合わせられる。
- **日付をまたぐシフト**：`work_date` は開始した日。勤務日の考え方（出勤した日の勤務）と同じ。
- **変更あり**：再公開で内容が変わったシフトには `revised_at` がある。

## 動作確認の方法
- 起動：`bin/rails server -p 3000`。今日は 2026-11-25（水）。開発 DB には、シフト・パターンが 0 件。
- 手順の例（管理者：山田 太郎 または 管理 次郎）
  1. 「管理」→「シフト作成」（`/admin/shifts`）を開く。今週（11/23〜11/29）の表が出る。
     - 11/23 の見出しが赤で、「勤労感謝の日」と出る。土曜は青、日曜は赤。
  2. 「シフトパターンを管理」で、次の3つを登録する。
     - 早番 9:00〜18:00・60分
     - 遅番 13:00〜22:00・60分
     - 夜勤 22:00〜6:00・60分（一覧で「22:00〜翌6:00」になる）
  3. シフト表で、従業 花子 の 11/26 のマスを押す。「夜勤」のボタンで入力して登録する。
     - マスに「22:00〜翌6:00・下書き」と出て、11/26 の人数が「1人」になる。
  4. 11/27 のマスで、開始 5:00〜終了 10:00 を入れる。前日のシフトと重なるエラーが出る。
     - 終了＝開始、休憩 600 なども試せる。
  5. 「パターンで割り当て」で「早番」を選ぶ。いくつかのマスを押す。
     - ページの位置を保ったまま、マスに入る。
     - シフトがあるマスを押すと、置き換わる。
  6. 「この週を公開」を押す。確認に件数が出る。公開すると「公開済み」と最終公開の日時が出る。
  7. 公開したマスを開いて時刻を変える。マスが「変更・未公開」「公開中 〜」になり、週の状態が「公開後の変更あり（未公開）」になる。
     - 削除すると「削除・未公開」になる。もう一度公開すると、履歴に「変更 1件」などと出る。
  8. 「翌週 →」→「前週をコピー」を押す。見込みの件数を確かめてコピーする。もう一度押すと、「すでにシフトがあるマス」の件数が出て、上書きしない。

## 既知の問題・懸念
- **従業員側の表示は無い（F12 の範囲）。** 「公開するまで従業員に見えない」は、データと管理者の画面で確かめた。従業員の画面は F12 で `Shift.published` と `published_*` を使って作る必要がある。
- **パターンで割り当てた後の位置の保持は、Turbo 8 の morph と自作の `scroll-keeper` コントローラに頼っている。**
  - morph の途中で、ブラウザが横スクロールを 0 に戻すことがあったため、描画の前後で位置を覚えて戻している。
  - JavaScript が無効なときは、通常のページ遷移になる（位置は戻る）。
- **公開は、ボタンを押した時点のその週の未公開の変更をすべて反映する。** 確認のダイアログを出した後に、他の管理者が加えた変更も一緒に公開される（件数の食い違いは、公開後のメッセージで分かる）。
- 375px では、ツールバーとパターンの欄が縦に長い。表は 88px 幅のマスで、1画面に約3日分しか見えない。日ごとの縦表示には切り替えていない。
- 承認待ちの休暇は、シフト表に出していない。
- 祝日のマスの背景は、ごく薄い赤。見出しほどは目立たない。
- 公開の履歴は、週ごとに最新5件だけを出す。
- 1人1日1件のため、同じ日に2回の勤務（分割シフト）は登録できない。
- 管理メニュー（ダッシュボード・月次集計）は、まだ無い。項目が増えても縦のリストなので、375px で窮屈にはならない想定。
