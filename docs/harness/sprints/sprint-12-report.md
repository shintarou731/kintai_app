## 実装内容

### データ

### 判定（遅刻・早退・欠勤）を1か所にまとめた
- **`ShiftCheck`**（`app/models/shift_check.rb`）：1人・1日分の予実比較。アプリで遅刻・早退・欠勤を判定するのはここだけ。
  - 入力：公開済みのシフト・その日の勤怠・その日の承認済みの休暇・現在時刻。
  - 出力：`late?`・`early_leave?`・`absent?`・`marks`・`late_minutes`・`early_leave_minutes`・`status`（`:no_shift`／`:on_leave`／`:absent`／`:upcoming`／`:not_clocked_in`／`:working`／`:missing_clock_out`／`:done`）。
  - `:not_clocked_in`（開始を過ぎたのにまだ出勤していない）は、F13 の「未出勤（遅れ）」にそのまま使える。
- **`HalfDayLeaveWindow`**（`app/models/half_day_leave_window.rb`）：半休が休みにする時間帯の定義。予実比較とシフト作成の両方で使う。
- **`MonthlyAttendance`** に、各日の `shift_check` と、月度の `late_count`・`early_leave_count`・`absence_count`・`scheduled_days_count`・`marked_days` を足した。
  - 勤怠履歴・管理者の予実の確認はここから読む。F14（月次集計）・F15（CSV）もここから読めば、画面と同じ値になる。

### スプリント 11 の評価の指摘の修正
1. **375px の「この週の公開の履歴」で、バッジが楕円になる**
   - 共通のスタイル（`.table--responsive`）で直した。375px のカード表示で、ラベル付きの欄を flex にせず、ラベルを左に置いて中身を普通の文章として流すようにした。
   - これで、欄の中身を1つの要素にまとめなくても、バッジや文字が flex の項目にならない。従業員一覧・承認・申請・休暇・付与・パターン・設定・予実の確認のすべての表に効く。
   - システムテストで、公開の履歴のバッジの高さが 28px 未満、内容の欄の高さが 52px 以下であることを確かめた。
2. **半休の日に、シフトが半休の時間と重なるかを判定しない**
   - 基準は下の「決めた扱い」のとおり（午前半休＝〜12:00、午後半休＝13:00〜）。
   - 重なっても登録はできる（警告だけ）。次の場所で知らせる。
     - **入力画面**：半休の説明と基準の時刻を出す。保存済みのシフトが重なっていれば、警告の色と「今のシフト（…）は、半休の時間と重なっています」。入力中も、プレビューに「午前半休の時間と重なっています」と出す（JS）。
     - **登録・変更**：保存した後のメッセージに注意を添える。
     - **パターンの割り当て**：重なるときだけ、注意つきのメッセージ（エラーの色）で出す。
     - **前週のコピー**：確認のダイアログと結果のメッセージに「半休の時間と重なるマス N件」を出す（コピーはする）。
     - **シフト表のマス**：「半休と重なる」と出す。
3. **割り当てのたびに上部にメッセージが入り、表が約80px 下にずれる**
   - 割り当ての結果は、ページの中に差し込まず、画面上部に重ねて出すメッセージ（トースト。`toast_controller.js`）にした。
   - 成功は5秒で消え、エラーは閉じるまで残る。閉じるボタンもある。
   - システムテストで、2回続けて割り当てても、表の上端の位置が変わらない（±1px）ことを確かめた。
4. **無効な従業員のシフトの画面**
   - 入力欄（`fieldset disabled`）と「変更を保存する」を押せないようにし、削除だけ押せるようにした。
   - 状態の表示と削除の確認の文言は、DB に保存されている値で出すようにした（`Shift#stored_state`・`#stored_range_label`）。そのため、422 で再表示しても、入力した値で「変更・未公開」と出ることはない。

## 決めた扱い（仕様に書かれていない点）

| 項目 | 決めた扱い |
|---|---|
| **予定に使う内容** | 公開済みの内容（`published_*`）だけ。<br>- 下書き（一度も公開していない）は「シフトなし」と同じ。<br>- 公開後に変えてまだ公開していない内容は使わない。<br>- 公開後に削除して、まだ公開していないシフトは、次の公開まで公開中の内容のまま使う（従業員の画面に見えているものと同じ）。 |
| **許容範囲と秒の扱い** | 秒を切り捨てた時刻で比べる（画面の時刻表示・実働の計算と同じ）。許容範囲は1分。<br>- **遅刻**：出勤（秒切り捨て）− 開始 が **2分以上**。9:00 開始なら、9:01:59 までは遅刻にしない。9:02:00 から遅刻（2分）。<br>- **早退**：終了 − 退勤（秒切り捨て）が **2分以上**。18:00 終了なら、17:59:00〜17:59:59 は早退にしない。17:58:59 は 17:58 として扱い、早退（2分）。 |
| **欠勤** | シフトの終了（半休の日は、半休を除いた働く時間の終わり）を過ぎても、その日の出勤の打刻が無く、休暇も無い日。<br>- 「過去の日」には、今日のうち終了を過ぎたシフトも含める。<br>- 打刻修正の申請中でも、承認されるまでは欠勤のまま。 |
| **当日（終わっていないシフト）** | 開始の前：「これから」（印なし）。<br>開始＋1分を過ぎて未出勤：「未出勤」（印ではない。回数に数えない）。<br>出勤すれば、遅刻はその時点で決まる。早退は退勤するまで決めない（勤務中）。<br>終了を過ぎても未出勤なら欠勤。 |
| **日付をまたぐシフト** | 終了は翌日の時刻として比べる（22:00〜翌6:00 なら、翌 5:58 の退勤は早退、翌 5:59 は早退ではない）。<br>勤怠とは「勤務日（出勤した日）＝シフトの日」で突き合わせる。欠勤は翌日の終了時刻を過ぎてから決まる。 |
| **休憩** | 判定に使わない。シフトの休憩時間と、実際の休憩の長さ・時刻は比べない。 |
| **全日の休暇（承認済み）** | 打刻があっても無くても判定しない（印なし。「休暇」）。種類が「欠勤」の休暇も、承認済みの休暇として扱い、欠勤の印は付けない。承認待ちの休暇は休暇として扱わない。 |
| **半休の時間帯** | 午前半休＝その日の 0:00〜12:00。午後半休＝その日の 13:00〜24:00。12:00〜13:00 は昼休みで、どちらにも含めない。 |
| **半休の日の判定** | - 午前半休：シフトの開始が 12:00 より前なら、出勤の基準を **13:00** にする（13:01 は遅刻にせず、13:02 は遅刻）。<br>- 午後半休：シフトの終了が 13:00 より後なら、退勤の基準を **12:00** にする（12:00 は早退にせず、11:58 は早退）。<br>- 反対側（午前半休の終了・午後半休の開始）は、シフトの時刻のまま判定する。<br>- 基準を動かして働く時間が残らない日（例：午前半休で 9:00〜12:30）は、全日の休暇と同じ扱い。<br>- 働く時間が残っているのに出勤の打刻が無ければ、欠勤。 |
| **半休との重なり（シフト作成）** | 午前半休の日に 12:00 より前に始まるシフト、午後半休の日に 13:00 より後に終わるシフトは「重なる」。<br>日付をまたぐシフトは、その日の分で判定する（午後半休の日の 22:00〜翌6:00 は重なる。午前半休の日は重ならない）。<br>重なっても登録はできる（警告だけ）。 |
| **退勤漏れの日** | 遅刻は判定する。早退は判定できないので付けない（「退勤漏れ（早退は判定できません）」と出す）。 |
| **シフトの無い日の勤務** | 印は付けない。 |
| **休日（土日・祝日）のシフト** | 平日と同じに判定する（シフトがあれば勤務の予定とみなす）。 |
| **「変更あり」** | 再公開で内容が変わったシフト（`revised_at` がある）。期限は設けず、ずっと出す。title に変更を公開した日時を出す。 |
| **月の範囲** | 従業員の「シフト」のカレンダーは、暦の月（1日〜末日）。<br>勤怠履歴と管理者の予実の確認の回数は、締め日（F6）に従う月度。 |
| **予実の確認の置き場所** | 管理メニューの「予実の確認」（`/admin/shift_reports`）。F14 の月次集計ができたら、同じ `MonthlyAttendance` の回数を表に入れる想定。 |

## 既知の問題・懸念
- **日付をまたぐシフトに、0:00 を過ぎてから出勤した場合**（例：22:00〜翌6:00 のシフトで、翌 0:30 に出勤）
  - 勤怠の勤務日は出勤した日（翌日）になるため、シフトの日と突き合わせられない。
  - その結果、シフトの日は「欠勤」、翌日は「シフトの無い日の勤務」になる（遅刻としては数えない）。勤務日の定義（出勤した日）に合わせた扱いとして残した。
- **今日のシフトでも、終了を過ぎて打刻が無ければ「欠勤」に数える。** 仕様の「過去の日」を「終わったシフト」と解釈した。
- **管理者の 375px のナビ**：項目が6つになり、「管理」が2段目に折り返す（横スクロールは出ない）。従業員は1段に収まる。
- **トースト**
  - 375px では、2段のヘッダーの上に重ねて出す（5秒で消える／閉じられる）。
  - トーストを使うのは、シフト表のパターンの割り当てだけ。他の操作は従来どおりページ上部のメッセージ。
- **共通の表のスタイルの変更**：375px のカード表示の、すべての `.table--responsive` に効く。システムテストは通っているが、既存の各画面の見た目は、全部をスクリーンショットで見比べてはいない。
- **カレンダーと回数の範囲**：カレンダーは暦の月、勤怠履歴・予実の確認の回数は締め日の月度。締め日を設定していると、カレンダーに見える印の数と、勤怠履歴の回数が一致しない月がある（カレンダーには月の回数を出していない）。
- **予実の確認の問い合わせ**：従業員1人につき数回の問い合わせになる。数十名までの想定。
- 種類が「欠勤」の承認済み休暇は休暇として扱い、欠勤の回数には数えない。F14 で「欠勤回数」に含めたい場合は、`ShiftCheck` か集計側で扱いを決める必要がある。
