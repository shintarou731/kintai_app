## generator が決めた扱いへの所見（合否には使っていない）
- **半休の人**
  - 半休の時間帯の最中は「休暇」、それ以外はシフトに基づく判定、という扱いは F12 の基準と一貫していて妥当。
  - 開発 DB に過去の日付の半休が無く、未来の日付は使えないため、ブラウザでは確かめていない。モデルのテスト（午前／午後・12:00〜13:01・13:02）が通っていることだけ確認した。
- **前日から勤務中の人**
  - 「勤務中」にして、「前日 23:58」と備考を出す扱いは分かりやすい。
  - 小さな点：前日の遅刻（「遅刻 1:58」）の印は、日付が変わると出勤の欄から消える。0:00 を過ぎると、遅れて来た人だと分からなくなる。
- **承認待ちの件数の数え方**
  - ナビのバッジと同じ「自分が処理できる件数」を大きく出し、全件との差を注記する扱いは、迷いにくく妥当。
- **退勤漏れの件数に、まだ退勤できる勤務を含める**
  - 勤怠履歴の「退勤漏れ」と同じ定義でそろえ、かつ「うち N件 はまだ退勤できます」「本人が退勤できます（〜期限）」で区別しているので、誤解は少ない。
  - ただし夜勤のある職場では、毎晩 0:00 を過ぎると赤いカードが点く。管理者が見慣れて、本当の漏れを見落とすおそれがある。
  - 赤い強調は「修正が必要」な件数だけにする案も検討の余地がある。
- **ログイン直後の画面をホームのままにした**
  - 管理者も打刻するので妥当。ダッシュボードは、管理メニューの先頭とホームのリンクから1クリックで開ける。
- **自動で更新しない**
  - 受け入れ基準は「再読み込みで最新」なので、矛盾しない。
  - 「〜時点」の時刻と「更新」ボタンがあり、Turbo のキャッシュも使わない（戻るでも最新）。使い勝手に問題は無い。
- **そのほか**
  - シフトの開始時刻を過ぎても許容範囲（1分）の間は、備考が「シフト前」のままになる（9:01:42 で確かめた）。実際はシフトが始まっているので、「開始直後」などの言い方のほうが正確。軽微。

## バグ（重要度順）
重大なバグは無い。

1. **[軽微] 375px で、備考の無い人のカードにも、空の「備考」の段が出る**
   - 再現手順：375px でダッシュボードを開く。山田・花子など、備考の無い人のカードを見る。

     - 原因：`.dashboard-table td.dashboard-table__note--empty { display: none; }`（詳細度 0,2,1）が、`.table--responsive td[data-label]:not(.table__primary) { display: block; }`（詳細度 0,3,1）に負けている。
2. **[軽微] 375px の退勤漏れの一覧で、「本人が退勤できます（〜11/13(金) 23:58）」のバッジが、カードの右端で切れる**

     1. `DEV_NOW` で、日付をまたいで勤務中の人を作る。
     2. 375px で `/admin/missing_clock_outs` を開く。
   - 期待される動作：期限まで読める（折り返す、または短く出す）。
   - 実際の動作
     - 「本人が退勤できます（〜11/13(金) 23:5」までしか見えない（`s13-missing-375.png`）。
     - `.table--responsive td .badge { white-space: nowrap; }` のため、折り返さない。
     - ページの横スクロールは出ない。

## 改善点（ジェネレーターへの具体的な指示）
- （バグ1）375px の空の備考を隠すルールの詳細度を上げる。例：`.table--responsive.dashboard-table td.dashboard-table__note--empty { display: none; }`。あわせて、375px で空の備考のセルが `display: none` であることを、システムテストで確かめる。
- （バグ2）退勤漏れの一覧の状況のバッジを、375px で折り返せるようにする。例：`.missing-clock-outs-table .badge { white-space: normal; }`。または、期限をバッジの外の小さな文字にする。
- （任意）許容範囲（開始〜1分）の間は、備考の「シフト前」を「シフト開始直後」などに変える。または、何も出さない。
- （任意）日付をまたいで勤務中の行で、前日の勤務の遅刻の印（「遅刻 1:58」）も出す。
