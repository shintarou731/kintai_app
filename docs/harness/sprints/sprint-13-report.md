# スプリント 13 実装レポート：管理者ダッシュボード（今日の出勤状況）（F13）

## 実装内容

### データ
- マイグレーションは追加していない。開発 DB には書き込んでいない（読み取りだけ。`PRAGMA query_only = ON` を付けた `bin/rails runner`）。

### モデル（判定・集計）
- **`AttendanceDashboard`**（`app/models/attendance_dashboard.rb`）：ダッシュボードの中身を1か所にまとめた。
  - 有効なユーザー全員について、今日の状態を判定する（下の「決めた扱い」の順番）。
  - 出す値：状態ごとの人数（`counts`）、遅れの人数（`late_count`）、表の並び（`sorted_rows`。遅れの人を先頭に出す）。
  - 遅れの判定は、F12 の **`ShiftCheck`** の状態をそのまま使う（`:not_clocked_in`、シフトの終了も過ぎた `:absent`）。自前の判定は持たない。
  - 要対応の値も出す。
    - 承認待ち：`ApprovalRequest.actionable_by`（ナビのバッジと同じ）。
    - 退勤漏れ：`MissingClockOutList`。
    - 残業の警告：`overtime_rows`。
  - 問い合わせ：前日・今日の勤怠、シフト、休暇を、全員分まとめて読む。
- **`MissingClockOutList`**（`app/models/missing_clock_out_list.rb`）：前日以前の退勤漏れの一覧。
  - ダッシュボードの件数と、一覧画面の件数は同じオブジェクトから出すので、必ず一致する。
- **`MonthlyAttendance.for_users`**（追加）：複数の従業員の月度の勤怠表を、まとめて作る。
  - 勤怠・休暇・修正申請・シフトを、4回の問い合わせで全員分読む。
  - 値は1人ずつ作ったときと同じ（テストで比較した）。
  - 残業の警告はこれを使う。スプリント12の既知の問題だった「予実の確認の問い合わせが人数に比例する」も、`ShiftReport` をこれに切り替えて直した。

### スプリント 12 の評価の指摘の修正
1. **今日のシフトが始まる前に退勤していると、「早退 21:36」の印が付く**
   - `ShiftCheck` に `left_before_start?` を加えた。シフトの開始より前に退勤した勤務は、シフトの終了を過ぎるまで早退を決めない。
   - その間の状態は `:left_before_start` にした。予実の確認の判定の欄には「シフトの開始前に退勤（早退はシフトの終了後に判定）」と出る。
   - シフトの終了を過ぎたら、これまでどおり早退として判定する。シフトの開始より後に退勤した勤務は、従来どおり退勤した時点で早退と決める。
   - 開発 DB で確かめた。花子（17:00〜22:00 のシフト、0:24 に出勤・退勤）と double（10:00〜19:00 のシフト、3:27 に退勤）は、どちらも `:left_before_start` になり、印は付かなくなった。
2. **1280px のシフト画面で、「次回のシフト」の「22:00〜翌6:00」が2行に折り返す**
   - 日付と時間帯を、それぞれ `.nowrap`（共通のクラスを新しく作った）で囲んだ。
   - システムテストの 1280px で、時間帯が1行の高さに収まることを確かめた。
3. **無効な従業員のシフトの画面に、「変更すると『変更・未公開』になり…」という説明が残っている**
   - 無効な従業員の、公開中のシフトでは「公開済みです（9:00〜18:00）。削除すると『削除・未公開』になり、週を『公開』するまで、従業員には今の内容が見えます。」に変えた。
   - 有効な従業員の場合は、従来の文言のまま。

## 決めた扱い（仕様に書かれていない点）

| 項目 | 決めた扱い |
|---|---|
| **一覧の対象** | 有効なユーザー全員。管理者も打刻するので、一覧と人数に入れる（「管理者」のバッジを付ける）。無効な従業員は出さない。 |
| **状態の判定の順番** | 上から順に、最初に当てはまったものにする。<br>1. 退勤していない勤務がある → **勤務中／休憩中**。ホーム画面の打刻と同じ基準（出勤から24時間以内。`TimeClock` と同じ）。<br>2. 今日を勤務日とする勤務が、退勤済み → **退勤済み**。<br>3. シフトの開始を過ぎても出勤していない → **未出勤（遅れ）**。<br>4. 休暇の日で、打刻が無い → **休暇**。<br>5. 前日に出勤して、今日の 0:00 以降に退勤した（夜勤明け） → **退勤済み**。<br>6. それ以外 → **未出勤**。<br>実際の打刻（1・2）を休暇より優先する。休暇の日に出勤した人は「勤務中」とし、休暇のバッジを添える。 |
| **遅れの基準** | F12 の `ShiftCheck` と同じ（公開済みのシフトだけ。許容範囲は1分。9:00 開始なら 9:02 から遅れ）。<br>- シフトの終了も過ぎて出勤が無い人（`ShiftCheck` の欠勤）も、今日の「未出勤（遅れ）」にする。備考に「シフトの終了（18:00）を過ぎても出勤がありません」と出す。<br>- 下書きのシフトでは判定しない。<br>- 出勤すれば遅れではなくなり、出勤の欄に「遅刻 0:12」の印が付く。 |
| **前日から日付をまたいで勤務中の人** | 「勤務中」（または「休憩中」）。<br>- 出勤の欄に「前日 22:00」と出す。<br>- 備考に「11/24(火) の勤務（日付をまたいで勤務中）」と出す。 |
| **前日からの夜勤明け（今日退勤した人）** | 「退勤済み」。出勤の欄に「前日 22:00」、退勤の欄に今日の退勤時刻を出す。<br>- 今日あとでシフトがあれば、出勤した時点で「勤務中」に変わる。<br>- 今日のシフトの開始を過ぎても来なければ、「未出勤（遅れ）」になる。<br>- 前日のうちに退勤した人は、今日は「未出勤」。 |
| **前日に始まる日付をまたぐシフトの途中** | 例：0:30 に見たときの 22:00〜翌6:00 のシフト。<br>- シフトの欄に「前日からのシフト 22:00〜翌6:00」と出す。<br>- まだ出勤していなければ「未出勤（遅れ）」にし、「前日からのシフト・22:00 開始から 2:30 経過」と出す（`ShiftCheck` の `:not_clocked_in`）。<br>- シフトの終了を過ぎたら、前日のシフトでは判定しない。 |
| **半休の人** | 打刻が無い間は、半休の時間帯の最中だけ「休暇」にする（`HalfDayLeaveWindow`。午前半休は 0:00〜12:00、午後半休は 13:00〜）。<br>- 午前半休（9:00〜18:00 のシフト）：12:00 までは「休暇」。12:00〜13:01 は「未出勤」。13:02 に未出勤なら「遅れ」（F12 の基準と同じく 13:00 が出勤の基準）。<br>- 午後半休：午前のシフトに来なければ「遅れ」。午前に働いて退勤すれば「退勤済み」。シフトが無く打刻も無ければ、13:00 から「休暇」。<br>- 半休でシフトの時間がすべて埋まる日（午前半休の日の 9:00〜12:30 など）は、一日中「休暇」。<br>- 半休のバッジ（「有給（午前半休）」）は、どの状態でも備考に出す。 |

### 日付をまたぐシフトに 0:00 を過ぎて出勤した場合（スプリント12の中程度の指摘）は、ダッシュボードで誤解を招くか
今回は判定を変えていない。ダッシュボードでの見え方は次のとおりで、**今日の状態としては誤解を招かない** と判断した。
- 例：22:00〜翌6:00 のシフト（11/24）、11/25 の 0:30 に出勤した場合。
  - **11/24 の 22:02〜23:59**：今日のシフトとして「未出勤（遅れ）」。
  - **11/25 の 0:00〜0:29**：前日からのシフトとして「未出勤（遅れ）」。日付が変わっても、遅れが消えない。
  - **0:30 に出勤した後**：「勤務中」。シフトの欄に「前日からのシフト 22:00〜翌6:00」が出る。
    - 出勤の欄に「遅刻」の印は付かない。この勤務は勤務日が 11/25 で、11/24 のシフトと突き合わせられないため。
    - 欠勤の印も出ない。ダッシュボードは今日の状態だけを出すため。
- 誤解の余地が残るのは、遅刻の印が出ない点だけ。勤務中であることと、前日からのシフトであることは正しく分かる。
- 「11/24 は欠勤」になる件は、勤怠履歴と予実の確認の回数の問題で、ダッシュボードには出ない。
- この件の仕様の判断が決まったら、`ShiftCheck` を組み立てる側（`MonthlyAttendance` と `AttendanceDashboard#previous_check_for`）で、前日のシフトと突き合わせる形に変える想定。

## 既知の問題・懸念
- **日付をまたぐシフトに 0:00 を過ぎてから出勤した場合**（スプリント12の中程度の指摘）は、判定を変えていない。
  - ダッシュボードでは「勤務中」と「前日からのシフト」が正しく出るが、遅刻の印は付かない（上の説明のとおり）。
- **シフトの開始前に退勤した勤務が、その日のシフトの勤怠になる**
  - 勤務日＝シフトの日で突き合わせ、同じ日に2回は出勤できないため、その日のシフトのための出勤はもうできない。
  - ダッシュボードでは「退勤済み」になり、遅れにはならない。シフトの終了後は、勤怠履歴で早退（シフトの終了までの分）になる。
  - 実態は「打刻の誤り」であることが多い。その場合は修正申請で直す運用になる。
- **自動更新はしない**：「更新」ボタンか、ブラウザの再読み込みで最新にする。
- **375px の人数のカード**：5枚を2列に並べるので、「休暇」のカードが3段目に1枚だけになる。
- **残業の警告の表**：その人の日ごとの残業を見る画面へは移れない。管理者向けの日別勤怠（F5 と同等の表）は F14 で作る想定なので、リンクは置かなかった。
- **退勤漏れの一覧**：管理者が直接、退勤時刻を入れる操作はない（F14 の直接修正で対応する想定）。今は本人の修正申請を承認して直す。
- **`MonthlyAttendance.for_users` に変えた `ShiftReport`**：テストは通っており、値は1人ずつ作ったときと同じ。ただし、予実の確認の画面は、ブラウザでは見直していない。
