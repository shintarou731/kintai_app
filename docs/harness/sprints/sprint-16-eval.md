## バグ（重要度順）
1. **[軽微]** 他の管理者が処理した申請の「新しい申請」通知が、未読のまま残る。
   - 再現手順：花子が休暇を申請する → 次郎が通知から開いて承認する → 山田のベルを見る。
   - 期待される動作：処理済みになった申請の通知は、未読の件数から外れる（自動で既読にする、または「処理済み」と表示する）。
   - 実際の動作：山田の 12/7・12/8 の通知は、次郎が処理した後も「未読」のまま、バッジに数えられていた。管理者が複数いると、未読の件数が「対応が必要な件数」より大きくなる（評価の終わりで、山田は未読 17件、ナビの承認は 4件）。
2. **[軽微]** 警告ラインを一時的に下げると、その月度の警告を「使い切って」しまう。
   - 再現手順：警告ラインを 2時間にする（警告が届く）→ 45時間に戻す。
   - 期待される動作：本当に 36時間・45時間を超えたときにも、警告が届く。
   - 実際の動作：80%・100% の記録が月度ごとに残っているため、同じ11月度にはもう届かない。開発 DB では、4名とも 2026-11 の 80%・100% が記録済みになった（`overtime_alerts` 8件。警告ラインが 60分・120分のときの記録）。
   - generator の決めた扱い（「下回ってからまた超えても送り直さない」）とは矛盾しない。ただし、「警告ラインの変更」の場合まで同じ扱いにするかは、検討の余地がある。
3. **[軽微]** 元の出来事が取り消されても、通知が残る。
   - 付与を削除しても、「有給休暇が1.5日付与されました」は残る。
   - 申請を取り下げても、管理者の「新しい申請」は残る（レポートの既知の問題）。
   - 押すと現状の画面に移るので、実害は小さい。

## 所見

### generator が決めた扱い
- **自分の操作は自分に通知しない**：仕様と矛盾しない。自己却下・自分の申請・自分への公開で、本人に通知が無いことを確かめた。操作した画面のフラッシュで分かるので、妥当。
- **管理者が1人だけで、その人が自分の申請を出したときは、誰にも通知しない**：仕様の「管理者は新しい申請で通知を受け取る」とは文言上ずれるが、本人が出した申請を本人に知らせる意味は無い。ナビの「承認」の件数にも出るので、妥当。
- **残業の警告を判定するタイミング**：退勤・承認・直接修正・設定の変更の4つで、いずれも実際に届いた（直接修正では、送り直さないことを確かめた）。勤務中には送らないため、長時間勤務の当日中には気づけない。ただし、ダッシュボードに警告の欄があるので、許容できる。
- **残業が減ってからまた超えても、送り直さない**：仕様の「それぞれ1回ずつ」に合う。ただし、警告ラインを下げて戻した場合の副作用がある（バグ2）。
- **通知が作られないことがある（送り直す仕組みが無い）**：通知は補助の情報で、承認の一覧・ダッシュボードという正本があるので、許容できる。`safely` で元の処理が失敗しないことは、コードとテスト（`notifier_test.rb:261`・`:282`、`overtime_alert_test.rb:202`）で確かめた。
- **開いたままの画面は自動で更新されない**：実際に、開いたままの画面のバッジは変わらなかった。一方で、「すべて既読」は開いた時点までに限るので、見ていない通知を既読にしてしまう事故は起きない。仕様の範囲では問題ない。
