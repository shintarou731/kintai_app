## 所見
- **一覧で「付与なし」と「当年度の付与なし」が両方出る件**
  - 実際の表示は「0日 付与なし／0日 当年度の付与なし」だった。2つは意味が違う。
    - 「付与なし」：付与が1件も無い。
    - 「当年度の付与なし」：期限切れの付与だけがある場合も含む（例：次郎は「0日／0日 当年度の付与なし」）。
  - そのため、情報としては誤りではない。冗長ではあるが、印が付かない理由が分かる利点の方が大きく、不合格の理由にはならない。上の改善点のとおり、0件の人だけ片方を省くのがよい。
- **削除は元に戻せない件**
  - 確認ダイアログで「元に戻せません（必要なら付与し直してください）」と伝えている。
  - 確認画面で「削除後の残日数」を予告し、理由も必須なので、誤操作の余地は小さい。
  - 付与し直せば、残日数は同じになる。その場合、履歴には「付与の削除」と新しい「付与」の両方が残るので、経緯も追える。
  - 仕様にも、元に戻す機能は求められていない。現状で許容できる。
- **付与日が未来の付与**
  - UI では登録できない（「今日までの日付」）。
  - 判定のロジック（`usable_during?`）が未来の付与日の付与を「付与あり」と扱うことは、`DEV_NOW` で確かめた。
- **山田の不足の解消**
  - 評価前の山田は、付与0件で有給1日を取得していた（超過 1日）。
  - 評価で 2026/11/26 に10日を付与したため、超過が解消され、残り 9日・印ありになった。
