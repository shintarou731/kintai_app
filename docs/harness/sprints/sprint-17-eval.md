# スプリント 17 評価：F2 追加分（アカウント情報画面）

## 判定：不合格

理由：画面幅 720〜820px（iPad の縦向き 768／810／820px を含む）では、管理者のヘッダーで「管理」メニューの開閉ボタンが歯車と名前に重なり、上をふさぐ。このため、**歯車も名前もクリックできない幅がある**（768px ではどちらもクリックできない）。受け入れ基準「管理者も歯車・名前からアカウント情報画面を開ける」を、よく使われる幅で満たしていない。主要な操作ができないので、重大なバグとして扱う。
ナビとユーザー欄が重なる現象そのものは、スプリント 17 より前からあった（歯車を隠して確かめた）。ただし、歯車を加えたことで重なる幅が広がり、このスプリントで足した入口がふさがれている。

375px と 1280px での表示、閲覧専用、他人の情報が見えないこと、有給の値の一致、ホームの「アカウント」欄の削除は、すべて確認できた。

## バグ（重要度順）
1. **[重大]** 管理者のヘッダーで、720〜820px では歯車か名前が「管理」メニューのボタンにふさがれる（768px では両方）。アカウント情報画面に入れない。
   - 再現手順：
     1. 山田（`admin@example.com`／`password123`）でログインする。
     2. 画面幅を 768px にする。
     3. ヘッダーの歯車をクリックする。続けて、名前もクリックする。
   - 期待される動作：アカウント情報画面に移る。
   - 実際の動作：
     - どちらをクリックしても、「管理」メニューの開閉ボタンが反応する。
     - Playwright では「`<summary aria-label="管理" …>` from `<nav class="header__nav nav">` subtree intercepts pointer events」と出て、クリックできない。
     - 見た目でも、「休暇」と「管理」の文字が、ベル・歯車・名前の上に重なっている（`.playwright-mcp/s17-header-admin-768.png`）。
   - 原因（観察から）
     - 601px 以上では、ナビとユーザー欄が1段に並ぶ。このとき、ナビ（`.header__nav`）の幅が中身より狭くなる（768px で client 187px／scroll 418px）。それでも `overflow` が `visible` のため、はみ出したナビの項目がユーザー欄の上に重なっている。
     - 歯車を `display:none` にして同じように調べると、768px で名前がふさがれるのは同じだが、歯車の分だけ重なる幅が狭くなる。つまり、もとからある不具合が、歯車の追加で悪化している。
2. **[中]** 601〜880px（従業員は 601〜約720px）で、ヘッダーのナビとユーザー欄が重なり、ナビの項目が押せない。文字も重なって読めない。

## 所見
- **440px 以下でアプリ名の文字を隠し、ロゴだけにする判断**：妥当。

# 第2回評価（修正1回目への評価）

## 判定：合格

前回の不合格の理由は2つとも直っている。
- [重大] 720〜820px で管理者がアカウント情報画面に入れない → 直った。768px の管理者で、歯車も名前も実際にクリックして `/account` に移った。
- [中] 601〜880px でナビの一部が押せない → 直った。指定の15幅と両方の役割で、押せない項目は0件。

前回の所見（戻り先）と軽微な指摘（状態・役割の文言、`SETTINGS_GEAR_PATH`）も直っている。受け入れ基準はすべて満たし、重大なバグは無い。
ただし、確かめる中で、通知のベルの一覧が 601〜679px で画面の左にはみ出す不具合を見つけた（バグ 1、[中]）。中身は押せるので重大ではないが、次の修正で直すことを勧める。

### テストの不安定さ（[軽微]、既存のテスト）

## 所見：1023px 以下で一覧がヘッダーの右端にそろって出ること
- **結論**：使い勝手の上で問題はなく、この方式は妥当と考える。
- **理由**
  - どの幅・どの名前でも、ベルの横の位置は一覧の左右の範囲の中にあった。一覧は、ヘッダーの下端に接して、ベルのすぐ下の高さから出る。ベルを押すとその下に一覧が広がって見えるため、どこから出たか迷わない。
    - 短い名前の管理者・601px：ベルの中心 281px、一覧 209〜589px
    - 従業員・768px：ベルの中心 508px、一覧 376〜756px
  - ベルが開いている間は、ベルの背景がアクセントの色になる。開いている状態は、ベルの側でも分かる。
  - スマホ（600px 以下）でも「ヘッダーの下に、画面の幅に合わせて出す」並びなので、狭い幅での出方がそろう。
  - ベルの位置に左右されないので、名前の長さや管理者バッジの有無で、はみ出しが再発しない。これは、ベルの真下に出す方式より確実。
- **気になる点**
  - 名前の長い管理者の 601px では、ベル（中心 224px）が一覧の左端（209px）の近くにくる。ベルから一覧の右端までは約 365px 離れる（`s17r3-bell-longname-601.png`）。それでも一覧はベルの真下から右へ広がるので、操作で迷うことは無い。
  - 1段目から2段目のナビにかぶって出る（ナビの「申請」「休暇」「管理」の上に重なる）。ただ、これはドロップダウンとして普通の見え方で、外を押す・Esc で閉じられるので問題ない。
  - 1023px と 1024px で、出方が「右端そろえ」から「ベルの真下」に切り替わる。この幅でウィンドウの大きさを変える人は少なく、気になりにくい。
