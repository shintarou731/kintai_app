# スプリント 3 実装レポート：出勤・退勤の打刻（F3）

## 実装内容

- **データ**（マイグレーション `db/migrate/20261124130000_create_attendances.rb`、テーブル追加のみ。既存のユーザー4人はそのまま）
  - `attendances`：`user_id`、`work_date`（勤務日＝出勤打刻をした日・JST）、`clock_in_at`、`clock_out_at`（勤務中は NULL）。
  - `(user_id, work_date)` に一意インデックス。同じ人が同じ日に2件目の出勤を作れない（二重送信の最終防衛線）。
- **モデル**
  - `Attendance`（`app/models/attendance.rb`）：検証（勤務日・出勤時刻必須、同じ日1件、退勤は出勤より後）、`worked_seconds` / `worked_minutes`（秒は切り捨て）、`overnight?`（日付をまたいだか）。
    - F4 への配慮：実働時間は `worked_seconds` の1か所で計算しており、休憩が入ったらここで差し引けばよい（休憩関連のコードは入れていない）。
  - `TimeClock`（`app/models/time_clock.rb`、DB を持たないクラス）：ある従業員の「今」の状態（未出勤／勤務中／退勤済み）と、出勤・退勤の打刻処理。
    - **日付またぎ**：「勤務中の勤務」＝退勤していない勤務のうち出勤から24時間以内のもの。前日 22:00 に出勤した勤務は翌日も「勤務中」になり退勤ボタンが押せ、出勤した日（`work_date`）の勤務として記録される。退勤後、その日（翌日）分はまだ未出勤なので出勤できる。
    - **退勤漏れ**：出勤から24時間を過ぎても退勤が無い勤務は「現在の勤務」として扱わない（翌日以降の出勤を妨げないため）。ホームに「退勤の打刻がない勤務があります」と赤枠で表示する。
    - **二重記録防止（サーバー側）**：出勤は「状態の確認」＋「一意インデックス」（同時に届いた2件目は `RecordNotUnique`／一意性検証で拒否し、正しいエラーメッセージを返す）。退勤は `clock_out_at IS NULL` を条件にした1回の UPDATE で書き込み、2回目は0件更新として拒否（最初の退勤時刻は上書きされない）。
- **画面・コントローラ**
  - `POST /clock_in`（`ClockInsController`）、`POST /clock_out`（`ClockOutsController`）。結果はホームへリダイレクト（PRG）して表示するので、再読み込みで再送信されない。
  - メッセージ：「出勤しました（09:02）」「退勤しました（17:45）。本日の実働時間は 8:45 です。」、日付またぎは「退勤しました（02:00）。11/23(月) の勤務として記録しました（実働 4:00）。」。拒否時は赤いメッセージ（「すでに出勤しています（09:00 に出勤）。…」「本日はすでに退勤済みのため、出勤できません（同じ日に出勤できるのは1回です）。」「すでに退勤しています（18:00 に退勤）。」「出勤していないため、退勤できません。…」）。
  - ホーム（`app/views/home/show.html.erb`）：現在の日付と時刻（秒まで・大きく）、状態表示（勤務中＝緑、未出勤・退勤済み＝グレー）、「出勤」「退勤」の大きなボタン（押せない方は `disabled` でグレー表示）、今日の出勤・退勤・実働時間。勤務中は実働時間がリアルタイムで進む。日付またぎ中は「11/23(月) 22:00 に出勤した勤務の続きです」と表示し、見出しも「11/23(月) の勤務（日付をまたいだ勤務）」になる。夜勤明けで当日の勤務が無いときは「前日（11/23(月)）の勤務：22:00〜02:00（実働 4:00）」を参考表示。
  - 時計（`app/javascript/controllers/clock_controller.js`、Stimulus）：1秒ごとに更新。**端末のタイムゾーンに関係なく日本時間**で表示し、**サーバーの時計に合わせる**（表示時にサーバー時刻を渡して端末とのずれを補正）。画面を開いたまま JST の0時を過ぎたら画面を読み込み直して「今日」の表示を更新する。
  - 二重クリック対策（ブラウザ側）：Turbo の送信中無効化に加え、送信中はボタンが「記録中…」になる。
- **開発用の時計変更（エバリュエーター向け）**：`config/initializers/development_clock.rb`。**開発環境だけ**、環境変数 `DEV_NOW` を付けて起動するとアプリの時計をその時刻から進める。有効な間は全画面の上部に黄色の注意書き（「開発用：アプリの時計を DEV_NOW で変更して動作中です（現在 …）」）が出る。本番・テストでは何もしない。
- **スプリント2評価の軽微な指摘の修正**
  1. 「最後の管理者」の同時実行対策：`User#save_keeping_active_admin` を追加。保存前の検証に加え、同じトランザクション（セーブポイント）内で**保存後に有効な管理者を数え直し、0人なら取り消す**。PostgreSQL 等向けに有効な管理者の行ロックも取る。`activate` / `deactivate` と従業員編集（`Admin::EmployeesController#update`）がこれを使う。
  2. 存在しない ID：`Admin::EmployeeNotFound`（`app/controllers/concerns/admin/employee_not_found.rb`）を従業員管理の3コントローラに追加。`/admin/employees/9999/edit` などは一覧に戻り「指定された従業員が見つかりません。一覧から選び直してください。」。従業員（非管理者）が開いた場合は従来どおり権限なしでホームへ。
  3. `.gitignore` に `/.playwright-mcp` を追加。

## 動作確認の方法

- 通常の起動：`bin/rails server -p 3000`（マイグレーションは適用済み）。ログインは `docs/harness/sprints/sprint-2-eval.md` のアカウント一覧（例：従業員 `double@example.com` / `password123`、`hanako@example.com` / `hanako2026`）。
- 基本操作
  1. ログイン → `http://localhost:3000/`。日付と時刻（秒）が進むこと、状態「未出勤」、「出勤」だけ押せることを確認。
  2. 「出勤」→「出勤しました（HH:MM）」、状態「勤務中」（緑）、出勤時刻が表示、「出勤」はグレーで押せない。実働時間が分単位で進む。
  3. F5（再読み込み）しても打刻は増えない。「出勤」をダブルクリックしても1件（DevTools で `disabled` を外して押す、または戻る→再送信 → 赤いエラーで件数不変）。
  4. 「退勤」→「退勤しました（HH:MM）。本日の実働時間は H:MM です。」、状態「退勤済み」、両ボタンが押せない。
  5. DevTools で「出勤」の `disabled` を外して押す →「本日はすでに退勤済みのため、出勤できません…」。
  6. 375px 幅で横スクロールが無いこと。
- **日付またぎの確認（`DEV_NOW` で時計を動かす。開発環境のみ）**
  1. サーバーを停止し、`DEV_NOW="<昨日の日付> 21:59:30" bin/rails server -p 3000` で起動（Git Bash の書式。PowerShell なら `$env:DEV_NOW="2026-11-23 21:59:30"; bin/rails server -p 3000`、終わったら `Remove-Item Env:DEV_NOW`）。画面上部に黄色の「開発用：アプリの時計を DEV_NOW で…」が出る。ブラウザの時計表示も 21:59 台になる。
  2. 打刻履歴の無いアカウント（例：`double@example.com`）でログイン、22:00 を過ぎたら「出勤」→「出勤しました（22:00）」。
  3. サーバーを停止し、`DEV_NOW="<今日の日付> 01:59:30"` で再起動 → ホームを開くと日付は翌日、状態「勤務中」、「11/23(月) 22:00 に出勤した勤務の続きです…」、見出し「11/23(月) の勤務（日付をまたいだ勤務）」、実働 3:59 前後、「出勤」は押せない。
  4. 2:00 を過ぎて「退勤」→「退勤しました（02:00）。11/23(月) の勤務として記録しました（実働 4:00）。」。状態は「未出勤」（その日の分はまだ）に戻り、「前日（11/23(月)）の勤務：22:00〜02:00（実働 4:00）」が表示される。
  5. 記録の確認（読み取りのみ）：`bin/rails runner 'p User.find_by(email: "double@example.com").attendances.map { |a| [a.work_date, a.clock_in_at, a.clock_out_at] }'` → 勤務日が前日になっている。
  6. 終わったら `DEV_NOW` なしで再起動する。
  - 注意：`DEV_NOW` は「起動時点をその時刻とみなす」だけで、時計は実時間で進む。**現実の今日より先（未来）の日付を指定すると、その日の打刻データが残り、後で本当にその日が来たとき「出勤済み」になる**ので、過去（昨日〜今日）の時刻を使うこと。打刻はアプリの画面で行うため、検証用のデータが開発 DB に残る（削除は不要だが、残る点に注意）。
- 管理側の修正の確認
  - 管理者で `http://localhost:3000/admin/employees/9999/edit` → 一覧に戻り「指定された従業員が見つかりません。一覧から選び直してください。」。`/admin/employees/9999/password/edit` も同様。
  - 同時実行対策はブラウザでは再現困難なため、モデルテスト（`test/models/user_test.rb` の「同時操作で保存前の確認をすり抜けても…」）で確認している。

## 既知の問題・懸念

- **24時間ルール**：出勤から24時間を過ぎても退勤が無い勤務は「退勤漏れ」とし、その勤務からは退勤できない（仕様に明記が無いため決めた。実際に24時間超の連続勤務があると退勤できない）。退勤漏れの修正手段は後続の申請機能（F7）待ちで、現状は「管理者に連絡してください」と案内するだけ。
- **出勤 0:00〜5:00 のケース**：仕様どおり「出勤打刻をした日」を勤務日とするため、例えば 1:00 に出勤すればその日の勤務になる。前日の勤務を 0 時過ぎに退勤してから同じ日にまた出勤することは可能（勤務日が別のため）。
- **同時実行対策（最後の管理者）**：SQLite では、ほぼ同時の2操作のうち後の方は「保存後の再確認で取り消し（エラーメッセージ表示）」か、まれに DB のロック待ちエラー（500）になる可能性がある。どちらでも有効な管理者が0人にはならない。実際の並行リクエストでの再現テストはしておらず、保存後チェックの動作をスタブで検証した。
- **`DEV_NOW`（開発用）**：`Time.now` を差し替えるため、有効中はログの時刻も変わる。過去の時刻にするとマイグレーションの日時検証に引っかかるため、有効中だけその検証を止めている。ファイル変更の自動リロードが効かない可能性があるので、コードを編集するときは `DEV_NOW` なしで起動すること。開発環境以外では動かない。
- **ホーム画面の見た目**：「ようこそ」カードを打刻カードに置き換えた（名前は見出し上の小さな文字に移動）。スクリーンショットでの目視確認はしていない。
- ブラウザでの日付またぎ自動リロード（開いたまま 0 時を越えたとき）は自動テストしていない。
