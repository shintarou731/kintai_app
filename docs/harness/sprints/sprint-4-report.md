# スプリント 4 実装レポート：休憩の打刻（F4）

## 実装内容

- **データ**（マイグレーション `db/migrate/20261124150000_create_attendance_breaks.rb`。テーブルを追加しただけで、既存のユーザー4人・勤怠2件はそのまま）
  - `attendance_breaks`：`attendance_id`、`started_at`（休憩開始）、`ended_at`（休憩終了。休憩中は NULL）。1つの勤怠に何件でも持てる（1日に複数回の休憩）。
  - 「`ended_at IS NULL` の行は勤怠ごとに1件まで」の部分一意インデックス。休憩開始が二重に届いても休憩中の休憩は1件しか作れない（二重送信の最終防衛線）。
- **モデル**
  - `AttendanceBreak`（`app/models/attendance_break.rb`）：検証（開始は必須・出勤より後、終了は開始より後）、`duration_minutes`。
  - `Attendance`：`has_many :breaks`、`open_break` / `on_break?`、`break_minutes`（休憩合計）、`worked_minutes`＝**出勤〜退勤 − 休憩合計**。休憩中の休憩は「今」までで数える。
  - `TimeClock`：状態に **`:on_break`（休憩中）** を追加。`start_break!` / `end_break!` を追加。
    - 勤務中：退勤・休憩開始が押せる。休憩中：休憩終了だけ押せる（**退勤不可**）。未出勤・退勤済み：休憩ボタンは押せない。
    - **二重記録防止**（F3 と同じ考え方）
      - 休憩開始：状態確認 ＋ 部分一意インデックス。同時に届いた2件目は一意制約で拒否し「すでに休憩中です（12:00 から）…」を返す。
      - 休憩終了：`ended_at IS NULL` を条件にした1回の UPDATE。2回目は0件更新として拒否し「すでに休憩を終了しています（13:00 に終了）。」。最初の終了時刻は上書きされない。
      - 退勤と休憩開始の競合：退勤の UPDATE に「休憩中の休憩が無い」条件を追加（休憩中には退勤しない）。休憩開始は同じトランザクション内で「まだ退勤していない」ことを UPDATE で確かめ、退勤済みなら取り消す。
    - **日付をまたぐ休憩**（例：20:00 出勤、23:30〜翌0:30 休憩、2:00 退勤）：休憩は出勤した日の勤怠に属し、翌日のホーム画面でも「休憩中」のまま休憩終了でき、休憩 1:00・実働 5:00 で記録される。
- **画面・コントローラ**
  - `POST /break_start`（`BreakStartsController`）、`POST /break_end`（`BreakEndsController`）。F3 と同じく PRG（結果はホームにリダイレクトして表示）。
  - メッセージ：「休憩を開始しました（12:00）」「休憩を終了しました（12:45）。今回の休憩は 0:45、休憩の合計は 0:45 です。」。退勤時は休憩があれば「本日の実働時間は 8:00 です（休憩 1:00）。」「11/23(月) の勤務として記録しました（実働 5:00、休憩 1:00）。」。
  - ホーム（`app/views/home/show.html.erb`）
    - ボタンを 2×2 に配置：1段目「出勤」「退勤」、2段目「休憩開始」（黄の枠線）「休憩終了」（黄の塗り）。押せないボタンは従来どおりグレー。
    - 状態表示に「休憩中」（黄）を追加。案内文も状態ごとに変更（休憩中は「休憩中は退勤できません」）。
    - 「今日の勤務」を4項目に：出勤／退勤／**休憩合計**（回数つき、休憩中は「（休憩中）」）／実働時間。
    - 「休憩の記録」一覧（1回目 12:00〜12:45 0:45、休憩中の行は黄色で「休憩中」）。
    - 「時間は分単位で計算します（打刻時刻の秒は切り捨て）。実働時間＝退勤−出勤−休憩合計。」の注記。
    - 夜勤明けの前日勤務の参考表示にも休憩を表示。
- **スプリント3評価の指摘への対応**
  1. **[中] 実働時間がリアルタイムに進まない**：`data-controller="clock"` を打刻カードからページ全体（`div.page`）へ移した。進行中の時間は新しいヘルパー `running_duration_tag` が `data-clock-target="duration"`・`data-started-at`・`data-base-minutes` を出力し、時計が「base ＋ 開始から今までの分数」で毎秒数え直す。勤務中は実働時間（base＝−休憩合計）が進み、**休憩中は実働時間を止め（更新対象にしない）、代わりに休憩合計が進む**。system テストで、表示を JS で書き換えても時計が正しい値に戻す（＝コントローラが更新している）ことと、休憩中は実働に更新対象が無いことを確認。
  2. **[軽微] 退勤再送信のエラー文**：「今日 0 時以降に退勤した勤務」を探すのをやめた。退勤ボタンは表示中の勤務の ID（`attendance_id`）を送り、拒否時は「その勤務（本人のもののみ）」か「今日の勤務」が退勤済みなら「すでに退勤しています（02:00 に退勤）。」、どちらでもなければ「出勤していないため、退勤できません。…」。評価の再現手順（11/23 22:00〜11/24 02:00 の勤務のあと 11/24 19:01 に退勤を POST）は「出勤していない」になる。日付またぎ勤務の退勤ダブルクリック（02:00:01 の再送）は従来どおり「すでに退勤しています（02:00 に退勤）」。ID はメッセージ選びにしか使わず、退勤する勤務の決定には使わない。
  3. **[軽微] 1280px のレイアウト**：ホームに `page--home`（`margin-inline: auto`）を付けて中央寄せ。打刻カードに `section` クラスを付け、「今日の勤務」との間に 16px の余白。ほかの画面（`page--narrow` を使うフォーム）には影響させていない。system テストで左右の余白が等しいこととカード間の余白を確認。
  4. **[軽微] 「3:59」問題**：**時間の計算を「分単位の打刻時刻どうしの差」に統一**した。打刻時刻は秒まで保存するが、出勤・退勤・休憩開始・休憩終了・「今」のすべてを秒切り捨て（画面に出る 09:02 などと同じ時刻）にしてから差をとる（`Attendance.minutes_between`）。サーバー（Ruby）と時計（JS）は同じ方法で数える。これにより 22:00:11 出勤 → 02:00:08 退勤は 4:00 になる（開発 DB の double の勤務も 3:59 → 4:00 と表示される）。秒の差を合計してから切り捨てる旧方式とは最大1分ずれることがある（例：09:02:30 → 18:05:00 は旧 9:02、新 9:03）。画面に出ている時刻から利用者が引き算した値と必ず一致するので、こちらを採用した。F5 の月合計もこの「日ごとの分」を足せば一貫する。

## 動作確認の方法

- 起動：`bin/rails server -p 3000`（マイグレーションは開発 DB に適用済み）。ログインは `docs/harness/sprints/sprint-2-eval.md` のアカウント（例：`double@example.com` / `password123`、`hanako@example.com` / `hanako2026`）。
  - 注意：花子は 11/24 分が退勤済み（スプリント3評価のデータ）なので、11/24 中に休憩を試すなら打刻履歴の無いアカウントか `double` を使う（double は 11/24 未出勤）。
- 基本操作（`http://localhost:3000/`）
  1. 未出勤：「休憩開始」「休憩終了」がグレーで押せない。
  2. 「出勤」→ 勤務中：「退勤」「休憩開始」が押せ、「休憩終了」は押せない。1分ほど開いたまま待つと「今日の勤務」の実働時間が再読み込みなしで進む（前回の指摘1）。
  3. 「休憩開始」→「休憩を開始しました（HH:MM）」、状態「休憩中」（黄）。押せるのは「休憩終了」だけ（退勤はグレー）。休憩合計が分単位で進み、実働時間は止まる（「（休憩中は停止）」）。「休憩の記録」に「1回目 HH:MM〜 休憩中」。
  4. 「休憩終了」→「休憩を終了しました（HH:MM）。今回の休憩は H:MM、休憩の合計は H:MM です。」、状態「勤務中」に戻る。
  5. もう一度 休憩開始→休憩終了 → 休憩合計に「（2回）」、一覧が2行。
  6. 「退勤」→「…本日の実働時間は H:MM です（休憩 H:MM）。」。休憩ボタンは両方グレー。実働＝退勤−出勤−休憩合計になっていること。
  7. 二重送信：各ボタンのダブルクリック、DevTools で disabled を外して押す、戻って再送信 → 件数が増えず、赤いエラー（「すでに休憩中です…」「すでに休憩を終了しています…」「休憩中のため、退勤できません…」「本日の勤務は退勤済みのため、休憩を開始できません。」「出勤していないため、休憩を開始できません…」）。
  8. 375px 幅・1280px 幅で表示（1280px で打刻カードが中央、カード間に余白）。
- 日付をまたぐ休憩（`DEV_NOW`、開発環境のみ。使い方は sprint-3-report.md と同じ。未来の日付は使わないこと）
  1. `DEV_NOW="<昨日> 23:29:30" bin/rails server -p 3000` で起動し、打刻の無いアカウントで「出勤」→ 23:30 を過ぎて「休憩開始」。
  2. サーバーを止め `DEV_NOW="<今日> 00:29:30"` で再起動 → ホームは今日の日付で「休憩中」、「<昨日> 23:29 に出勤した勤務の続きです」、休憩合計 0:59 前後で進行中。0:30 を過ぎて「休憩終了」→ 今回の休憩 1:00。
  3. 「退勤」→「<昨日> の勤務として記録しました（実働 …、休憩 1:00）。」
  4. 確認（読み取りのみ）：`bin/rails runner 'a = User.find_by(email: "<アカウント>").attendances.order(:work_date).last; p [a.work_date, a.breaks.map { |b| [b.started_at, b.ended_at] }, a.worked_minutes, a.break_minutes]'`

## 既知の問題・懸念

- **計算方法の変更（分単位）**：F3 時点の「秒の差を切り捨て」から変えたため、同じ勤務でも最大1分違う値になる（double の勤務は 3:59 → 4:00）。DB の値は変えておらず、表示・計算だけが変わる。F6 以降で丸めルール（15分単位など）を入れる場合は `Attendance.minutes_between` を起点に検討が必要。
- **休憩を終えずに帰った場合**：休憩中のままでは退勤できない。出勤から24時間を過ぎると「退勤漏れ」扱いになる（F3 と同じ）。打刻の修正は F7（修正申請）待ち。
- **`attendance_id`（退勤フォームの hidden パラメーター）**：拒否時のメッセージ選択にだけ使い、本人の勤怠以外は無視する。改ざんされても記録内容には影響しない。
- **SQLite の同時実行**：休憩開始と退勤がほぼ同時に届いた場合の整合性は、SQLite の書き込み直列化と条件付き UPDATE に頼っている。モデルテストで「画面表示時点の古い状態」からの競合は確認したが、実際の並行リクエストでの再現はしていない。
- **ボタン4つ**：勤務中以外はグレーのボタンが3つ並ぶ。押せるボタンは色付きなので判別はできるが、見た目の好みは分かれる。
- 「休憩の記録」の個別の時刻修正・削除はできない（仕様外。F7 の範囲）。
