## 判定：合格

受け入れ基準 5 件はすべて、開発サーバー（`bin/rails server -p 3000`）と Playwright MCP で実際に操作して確認した。所定労働時間と締め日の変更は、double@example.com の既存データで画面の値と手計算が一致した。不正な値は 27 パターンすべて 422 で保存されなかった。従業員は表示・URL 直打ち・PATCH/PUT のどれでも拒否された。スプリント5の軽微な指摘（退勤期限の表示と判定が最大59秒ずれる）も、画面で解消を確認した。重大なバグはない。375px で「締め日ごとの範囲」表の右端がわずかに切れる軽微なバグが1件ある。

### スプリント5の軽微な指摘（退勤期限の表示と判定のずれ）— 解消を確認
- 読み取り専用の計算（`bin/rails runner`、保存なし）で確認：ID 6（11/10 10:00:08 出勤）の期限は 11/11 10:00:00。09:59:59 と 10:00:00 は `clock_out_open?` が true で、`TimeClock#current_attendance` も ID 6 を返す。10:00:01 と 10:00:08 はどちらも false／nil で、履歴とホームの判定が一致した。
- 画面で確認：`DEV_NOW="2026-11-11 09:59:00"` で起動し、double のホームを約4秒ごとに観測した。09:59:56 までは「勤務中」で退勤ボタンが有効、表示は「11/11(水) 10:00 まで」。**10:00:00 以降は「未出勤」で退勤ボタンが無効**になり、表示と実際の切り替わりが一致した（以前は 10:00:08 まで押せた）。退勤ボタンは押していないので、データは増えていない。

## バグ（重要度順）
1. **[軽微] 375px で「締め日ごとの『1か月』の範囲」表の右端が切れる**
   - 再現手順：admin で `/admin/settings` を幅 375px で開き、下の表を見る。
   - 期待される動作：期間「11/1(日)〜11/30(月)」が全部見える（折り返し、または縦積みの表示）。
   - 実際の動作：表の幅 359px が、カード（`section.card.card--flush`、`overflow: hidden`、右端 363px）からはみ出す。期間の1行目末尾の「〜」が 3〜11px 切れる（テキストの右端は 366〜374px）。ページ自体の横スクロールはない（`scrollWidth=375`）。日付は2行に折り返して読めるので、実害は小さい。スクリーンショット：`.playwright-mcp/s6-settings-375-error.png`。
2. **[軽微] `work_rule_setting` パラメータをまるごと欠いた PATCH は 400 の素のエラー画面になる**
   - 再現手順：admin で `_method=PATCH` と `authenticity_token` だけを `/admin/settings` に POST する。
   - 期待される動作：設定画面にエラーを出す、または設定画面へ戻す。
   - 実際の動作：`ActionController::ParameterMissing` で 400 になる。UI からは起きず、データへの影響もない。

## 改善点（ジェネレーターへの具体的な指示）
- 375px では、早見表の期間セル（`td`）を `white-space: normal`・`word-break: keep-all` などで「〜」の後ろで折り返させる。または、この表をスマートフォン幅で縦積みのカード表示（勤怠履歴と同じ方式）にして、カードからはみ出さないようにする。375px でカード内の要素の右端がカードの右端を超えないことをシステムテストに足す。
- （任意）`setting_params` で `params.fetch(:work_rule_setting, {})` を使い、パラメータが欠けても 422 で設定画面を表示する。

## 所見
- **依頼外で追加された「勤怠履歴の警告ライン表示」**：総残業時間の下に小さく「警告ライン 45時間」と出し、超過時だけ赤字で「警告ライン（1時間）を超えています」（`rgb(185,28,28)`）にする。確認はしたが、控えめで、F13（ダッシュボード）や F16（通知）の先取りにはなっていない。従業員が自分の残業を意識できる点はよい。ただし仕様にはない表示なので、残すかどうかはオーケストレーター経由でユーザーに確認するのが望ましい。合否には影響させていない。
- **ルール変更が過去の月にもさかのぼって反映される点**：所定を 7:00 にすると、過去の 10月（10/31 の残業 0:00 → 1:00）も変わることを確認した。締め日を変えると、`?month=2026-11` の意味も月末締めの 11/1〜11/30 から 10/21〜11/20 に変わる。設定画面に「過去の月を含む勤怠履歴の表示に反映されます」と明記されており、F6 の受け入れ基準の範囲では問題ない。ただし F14（月次の締め）で確定した月の数字が後から変わると、給与計算と食い違う。F14 では「締めた月は締めた時点のルール（または確定値）を保持する」かどうかを仕様で決める必要がある。ユーザーに確認すべき点として挙げる。
- 標準の休憩時間は保存のみで、計算には使われていない（画面のヒントに明記されている）。受け入れ基準は「変更・保存できる」ことなので満たしている。
