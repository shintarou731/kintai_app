# スプリント 6 実装レポート：勤務ルール設定（管理者）（F6）

## 実装内容

マイグレーションを1つ追加した（新しいテーブルを作るだけで、既存のテーブル・データには触れない）。`bin/rails db:migrate` 済み。開発 DB は ユーザー4・勤怠11・休憩6 のまま、設定テーブルは 0 件（＝初期値で動作）。

- **設定の保存先** `work_rule_settings` テーブル（`db/migrate/20261124170000_create_work_rule_settings.rb`）／`app/models/work_rule_setting.rb`
  - 組織で1件だけ持つ（`singleton_key` 列の一意制約で2件目を作れない）。列：所定労働時間（分）・標準の休憩時間（分）・締め日（15/20/25、NULL＝月末）・警告ライン（時間）・最終更新者。
  - **行が無いあいだは初期値**（所定 8:00・休憩 1:00・月末締め・警告ライン 45時間）で動く。`WorkRuleSetting.current` は保存済みの行、無ければ初期値の未保存レコードを返す。初期値は `WorkRules` の定数・DB の列の既定値とそろえた（テストで一致を確認）。
  - 入力チェック（エラーは画面上部の「入力内容を確認してください（N件）」と、各入力欄の赤枠で表示。入力した値は欄に残す）
    - 所定労働時間：時:分（「8:00」「08:00」「7:30」、時だけの「8」、全角「８：００」も可）。**0:01〜24:00**。負の値（「-1:00」「−8:00」）→「マイナスにできません」、24:00 超（「24:01」「25:00」）→「24:00 以下にしてください（24時間を超える値は設定できません）」、「0:00」→「0:00 より長くしてください」、「8:60」「abc」→形式のエラー、空欄→「入力してください」。
    - 標準の休憩時間：0:00〜24:00（負・24時間超・形式の誤りはエラー）。
    - 締め日：月末／15日／20日／25日 のみ。画面を通さずに「10」「31」「abc」などを送ってもエラー（黙って月末扱いにはしない）。
    - 警告ライン：1〜744 の整数（744＝31日×24時間）。0・負・小数・文字・空欄はエラー。
- **計算に使うルール** `app/models/work_rules.rb`
  - `WorkRules.current` が保存された設定を読むように差し替えた（スプリント5で用意した差し替え口）。標準の休憩時間・警告ラインも持つようにした。勤怠履歴の計算はこれまでどおり `WorkRules.current` だけから値を受け取る。
- **設定画面** `GET/PATCH /admin/settings`（`Admin::WorkRuleSettingsController`、`Admin::BaseController` を継承＝管理者のみ）
  - ヘッダーの「管理」メニューに「設定」を追加（表示中は選択状態）。管理者のホームの「アカウント」にも「勤務ルールを設定する」リンク。
  - 4項目のフォーム（各欄に範囲・初期値・意味のヒント）、「保存する」「入力を取り消す」。
  - 「最終更新：2026年11月24日(火) 20:20（管理 太郎）」、未保存なら「まだ保存されていません。初期値（…）で動作しています。」。
  - 保存すると変わった項目をメッセージで知らせる（例：「勤務ルールを保存しました（1日の所定労働時間 8:00 → 7:00、締め日 月末 → 20日）。勤怠履歴の計算に反映されます。」）。何も変えなければ「変更はありません」。
  - 「締め日ごとの『1か月』の範囲」表：今日が属する月度と期間を4つの締め日それぞれで表示し、現在の設定の行に「現在の設定」バッジ（例：11/24 なら 20日締め＝2026年12月度 11/21(土)〜12/20(日)）。
  - まだ1件も無いときに2人の管理者が同時に保存した場合は、一意制約で失敗した側が先に保存された行に同じ値を書き込む。
- **勤怠履歴への反映**（`app/views/attendances/index.html.erb`）
  - 残業時間：所定労働時間の設定で計算（例：所定 7:00 で実働 8:00 の日は 1:00）。合計の注記「所定労働時間（7:00）」も設定値。
  - 「1か月」の範囲：締め日に従う。20日締めなら「11月度」＝10/21〜11/20。**初期表示は今日が属する月度**（11/24 なら 12月度＝11/21〜12/20）、前後の移動も月度単位、見出しは「2026年12月度」。
  - 締め日ありのときは表記を「月度」にした：「今月度」バッジ・ボタン、「← 前月度」「翌月度 →」、「この月度の合計」。期間の横に「（20日締め）」「（月末締め）」を表示。
  - ホームの「退勤漏れの勤務があります」のリンクも、締め日に従ってその勤務日が属する月度を開く（スプリント5で `WorkRules.current.period_containing` を使っていたため、そのまま反映される。1回だけ読むように整理した）。
- **警告ラインの使い方（独自に追加・控えめ）**：勤怠履歴の「総残業時間」の下に小さく「警告ライン 45時間」を表示し、その月度の総残業時間が警告ラインを**超えた**ときだけ赤字で「警告ライン（45時間）を超えています」にする（ちょうど 45:00 は超えていない扱い）。通知（F16）やダッシュボード（F13）、80% の判定は作っていない。
- **標準の休憩時間**：設定・保存のみ。計算や他の画面では使っていない（ヒントに「実際の休憩は打刻した時間で計算します」と明記）。
- **スプリント5評価の軽微な指摘（退勤期限の表示が分までで最大59秒ずれる）**：**期限を分単位に切り下げて判定する**形で直した。
  - 期限＝「出勤時刻の秒を切り捨てた時刻＋24時間」（10:00:08 出勤なら期限は翌日 10:00:00。表示「11/11(水) 10:00 まで」と一致）。`TimeClock.clock_out_deadline_for` に1か所でまとめ、`Attendance#clock_out_deadline`／`#clock_out_open?`（勤怠履歴の「ホームで退勤可」）と `TimeClock#current_attendance`／`#missing_clock_outs`（ホームの退勤ボタン・退勤漏れのお知らせ）の判定を同じ基準にした。DB の検索条件は「出勤時刻 ≥ (今−24時間) を分に切り上げた時刻」で同じ判定になる（`TimeClock.earliest_open_clock_in`）。
  - 影響：秒の分だけ、退勤できる期限が以前より最大59秒早くなる（以前は表示より遅くまで押せた）。
  - 夜勤中の「退勤漏れ」表記はユーザー確認待ちのため変更していない。

## 既知の問題・懸念

- **ルールの変更は過去の月にもさかのぼって反映される**：設定の履歴（いつから有効か）を持たないため、所定労働時間や締め日を変えると過去の月の残業・範囲も新しいルールで計算し直される（設定画面に注意書きあり）。月度の締め（F14）で確定した値を保持するかは F14 で決める必要がある。
- **締め日を変えた直後の月度のつながり**：例えば月末締め→20日締めに変えると、11月（11/1〜11/30）だったものが 11月度（10/21〜11/20）と12月度（11/21〜12/20）に分かれる。切り替えの前後で期間が重なったり抜けたりする扱いは考慮していない（常に現在の締め日で全期間を計算する）。
- **URL の `month` は締め日によって意味が変わる**：`?month=2026-11` は月末締めでは 11/1〜11/30、20日締めでは 10/21〜11/20 を表示する。ブックマークしたリンクの範囲が設定変更で変わる。
- 標準の休憩時間はまだどこでも使っていない（設定・保存のみ）。
- 警告ラインの「超えた」は `>`（45:00 ちょうどは超えていない）。F13・F16 で 80%・100% を判定する際は同じ基準 `WorkRules#overtime_warning?` を使うか、そのとき決める。
- 設定の同時編集（2人の管理者が別々に画面を開いて保存）は後から保存した方が勝つ（楽観ロックは無い）。
- 退勤期限の修正で、秒の分（最大59秒）だけ以前より早く退勤できなくなる。
- 開発サーバー＋Playwright での目視確認はしていない。
