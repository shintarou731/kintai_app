# スプリント 7 評価：打刻修正申請（F7）

## 判定：合格

受け入れ基準 7 件は、開発サーバー（`bin/rails server -p 3000`、`DEV_NOW` なし、実時刻 2026-11-24 22:51〜22:58 JST）と Playwright MCP で操作して確認した。ただし「承認・却下済みの申請は取り下げられない」の後半は、F8 が未実装のため画面では作れない。DB の書き換えもしていないため、この部分は自動テストとコードの確認で判断した。画面での確認は F8 の評価で行う。
勤怠記録は、申請の前後で全行・更新日時とも変わらないことを `bin/rails runner`（読み取りのみ）で確認した。スプリント6の軽微な指摘 2 件も解消していた。
重大なバグはない。中程度のバグが 1 件ある。同じ日への申請を 6 件同時に直接送信すると、2 件が SQLite のロックで 500 エラーになる。重複は作られず、UI のダブルクリックでは起きない。

### スプリント6の軽微な指摘 — 2 件とも解消を確認
1. **375px で「締め日ごとの範囲」表の「〜」が切れる**：admin で `/admin/settings` を 375px で開くと、表は縦積みのカード表示（「月度」「期間」の見出し付き）になった。

   - `scrollWidth=375`。「11/1(日)〜11/30(月)」は欠けずに見えた（`.playwright-mcp/s7-settings-375.png`）。
2. **`work_rule_setting` を欠いた PATCH**：`_method=patch` とトークンだけを送ると 422 になり、「保存する内容が送信されませんでした。入力欄に値を入れて「保存する」を押してください。」と出た。`work_rule_setting=abc` でも同じ。設定の DB は変わらなかった（所定 480・月末・updated_at 22:25 のまま）。

## バグ（重要度順）
1. **[中] 同じ日の申請を同時に送ると、一部が 500 エラー（`SQLite3::BusyException: database is locked`）になる**
   - 再現手順：double でログインし、CSRF トークン付きで同じ内容の `POST /requests/corrections`（例：11/9、09:00〜18:00、休憩1回）を 6 件並行で送る。
   - 期待される動作：1 件だけ作成され、残りは「すでに承認待ちの修正申請があります」の画面（または入力画面のエラー）になる。
   - 実際の動作
     - 1 件作成、3 件は既存の申請の詳細へ誘導、2 件は 500 の例外画面になった。
     - サーバーログは `ActiveRecord::StatementInvalid (SQLite3::BusyException: database is locked)`（`AttendanceCorrectionRequest#submit` の save 中、約 50ms で失敗）。
     - Rails 7.2 の SQLite は既定で DEFERRED トランザクションのため、検証の SELECT の後に INSERT しようとして、ロックの昇格に失敗すると考えられる。
     - データは壊れず重複もない。UI のダブルクリックではボタンが無効化され、POST は 1 回しか送られないので、通常の操作では起きない。

## 改善点（ジェネレーターへの具体的な指示）
- `AttendanceCorrectionRequest#submit` で `ActiveRecord::StatementInvalid`（`SQLite3::BusyException`）を捕捉し、`errors.add(:base, …)`（「同時に送信されたため保存できませんでした。申請の一覧を確認してください」など）を付けて false を返す。これで 500 ではなく入力画面のエラー、または既存申請への案内になる。
  - 根本的な対策の候補：`config/database.yml` の SQLite 設定で、書き込みトランザクションを IMMEDIATE にする（Rails 7.2 なら `default_transaction_mode: immediate` が使えるか確認）。打刻（`TimeClock`）など、他の書き込み処理への影響も確認すること。
- 同時送信 6 件で 500 が出ないことを確かめるテストを足す（スレッドを使う、または `save` が BusyException を投げるスタブを使う）。
- （任意）勤怠履歴の「修正申請」リンクを目立たなくする。例：通常の日は小さめの淡い色にして、退勤漏れの日だけ強調する（所見参照）。
