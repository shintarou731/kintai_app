### モデル
F8 の承認処理（`ApprovalRequest` の STI＋フック）に、そのまま乗せた。
- **`LeaveRequest`（休暇申請、種類名「休暇」）**
  - 入力の確かめ（申請時）
    - 種類・区分・理由は必須。
    - 終了日が開始日より前なら不可。終了日が空なら、開始日と同じ1日の休暇にする。
    - 半休は1日だけ（開始日＝終了日）。
    - 1回の申請は31日まで。
    - 日付は今日から前後1年の範囲。
    - 有給休暇で、土日だけの期間は不可（日数が0日になるため）。
    - 承認待ち・承認済み（取り消されていない）の休暇と、1日でも重なれば不可。午前半休と午後半休でも、同じ日なら重なりとして扱う。
  - 同時送信
    - `#submit` は、確かめと保存を1つの書き込みトランザクションで行う。SQLite は BEGIN IMMEDIATE で直列になる。PostgreSQL などでは申請者の行をロックする。
    - 同じ開始日の承認待ちが一意制約に当たった場合や、ロック競合の場合は、例外にせずエラーとして返す。
  - 承認時の再検証：`approval_blockers` で、承認済みの他の休暇と重ならないかを確かめ直す。
  - 承認・却下・取り下げのメッセージ用に、種類ごとの説明（`approval_result_note`／`rejection_result_note`／`withdrawal_result_note`）を持つ。
  - **F10 への備え**
    - `chargeable_days`：土日を除いた日数 ×（全日 1／半休 0.5）を Rational で返す。
    - `chargeable_days_within(range)`：月度などの範囲に入る分の日数。
    - `effective` スコープ：承認済みで、取り消されていない休暇。
    - F10 では、承認時（`approval_blockers`／`apply_approval!`）で残日数を減らし、取消申請の承認（`LeaveCancellationRequest#apply_approval!`）で戻せばよい。
- **`LeaveCancellationRequest`（取消申請、種類名「休暇取消」）**
  - 対象日は、取り消す休暇の開始日。
  - 出せる条件（申請時に DB を読み直して判断する）
    - 自分の休暇であること。
    - 承認済みで、取り消されていないこと。
    - 開始日が明日以降であること。
    - 承認待ちの取消申請が無いこと。同時送信は DB の一意制約で1件に絞る。
  - 承認すると、休暇の `cancelled_at` を入れる。休暇の状態は「承認済み」のまま残し、「取消済み」として表示する。処理者・コメントの履歴を残すためである。
  - 却下・取り下げなら、休暇は有効のまま。
  - 承認時の再検証：休暇がすでに取り消されていないか、承認済みかを確かめる。
- **`ApprovalRequest`**
  - `target_label` を追加した（休暇では「11/26(木)〜11/27(金)」の形）。
  - 却下・取り下げの説明のフックを追加した。
  - `actionable_by(admin)` を追加した。自己承認ルールに従い、処理できる承認待ちの申請を返す。
- **`MonthlyAttendance`**：その月度にかかる休暇（承認済み・承認待ち）を読み込む。`leaves_on(date)` と、種類ごとの日数（`leave_day_totals`）を出す。

### 画面
- **ナビ**に「休暇」を追加した（申請の右）。
- **休暇画面** `GET /leaves`
  - 入力フォーム
    - 種類と区分は、押しやすいボタン型の選択肢。
    - 期間は、開始日〜終了日の日付入力。
    - Stimulus `leave-form`
      - 半休を選ぶと、終了日を開始日に合わせて読み取り専用にする。
      - 開始日より前の終了日は、開始日に直す。
      - 「日数：0.5日・期間 1日間」のように日数を表示する。
      - JavaScript が無くても、サーバー側で同じ確かめをする。
  - 申請の結果
    - 成功：一覧の該当行を強調し、上部に「12/2(水) の有給休暇（午前半休）を申請しました（承認待ち）…」と出す。
    - 失敗：422 で、上部のメッセージとフォームの上の両方にエラーを出す。入力した内容は残す。
  - 一覧
    - 「これからの休暇」（終了日が今日以降、開始日の早い順）と「すべて」（新しい順）のタブがある。
    - 列は 期間・種類・区分・日数・状態（処理者、取消申請中・取消済み）・詳細。
- **休暇の詳細**（既存の `/requests/:id` を種類ごとの部分テンプレートに分けた）
  - 「休暇の内容」カード：種類・区分・期間（N日間）・日数・勤怠履歴での表示。
  - 承認待ち：「この申請を取り下げる」。
  - 承認済みで開始日が明日以降：取消申請のフォーム（理由必須、確認ダイアログあり）。`POST /leaves/:id/cancellation`。
  - 取消申請中：注意枠を出し、その取消申請へのリンクを出す。
  - 開始日を過ぎた休暇：取消申請できない理由を出す。
  - 取消済み：取消日時を出す。過去の取消申請の履歴も出す。
  - 取消申請の詳細：「取り消す休暇」を表示する。承認待ちなら「この取消申請を取り下げる」（休暇は有効のまま）。
- **申請一覧（本人）**
  - 休暇・休暇取消も並ぶ。対象日は期間、内容は「有給休暇・全日（3日・土日を除く）」の形。
  - 「休暇」画面への案内を追加した。
- **承認画面（管理者）**
  - 一覧：休暇・休暇取消が、打刻修正と同じ一覧に並ぶ。
  - 詳細
    - 「休暇の内容」を表示する。
    - 期間中に勤務の記録があれば注意を出す。
    - 取消申請の処理が遅れて開始日を過ぎていれば注意を出す。
    - 承認できない理由（重なり）があれば、「承認する」を押せなくして理由を出す。
    - 確認ダイアログと説明文は、種類ごとに変えた（「承認すると、休暇が確定し、本人の勤怠履歴の該当日に「有給（午前半休）」と表示されます」など）。
  - 処理後のメッセージ：「〇〇 さんの 11/26(木)〜11/27(金) の休暇申請を承認しました。勤怠履歴の該当日に「有給（全日）」と表示されます。」
  - 処理済みの一覧では、取り消された休暇に「取消済み」のバッジを並べる。
- **勤怠履歴**
  - 承認済みの休暇は、備考欄にティールのバッジ「有給（全日）」「有給（午前半休）」「特別休暇（全日）」「欠勤（全日）」で出す。行の背景も薄く色付けする。
  - 承認待ちは点線枠で「有給（全日）・申請中」と出す。取消申請中は「有給（全日）・取消申請中」。
  - バッジを押すと、休暇の詳細を開く。
  - 「この月の休暇（承認済み）：有給 2日・特別休暇 0.5日（土日は数えません）」と「休暇を申請する」リンクを、合計の下に出す。
  - 凡例に休暇を追加した。
  - 375px では、勤務の無い日でも休暇の表示を出す。

### スプリント8評価の指摘への対応
1. **422 のときエラーが画面上部に出ない**：承認・却下が失敗したとき、`flash.now[:alert]` で上部に「却下できませんでした：コメントを入力してください（…）」のように出すようにした。下部のフォーム内のエラーも残している。
2. **退勤空欄の申請で、退勤行に「変更」の印が付く**：今の記録も申請も退勤なし（「未打刻」と「空欄（勤務中）」）なら、退勤行を変更扱いにしないようにした（`correction_comparison_rows`）。
3. **承認待ちバッジに、自分では処理できない自分の申請も数える**
   - ナビとホームの件数を `ApprovalRequest.actionable_by(current_user)` にした。有効な管理者が2人以上なら、自分の申請を除く。
   - 一覧のタブは、従来どおり全件を数える。
   - 自分の申請がある場合は、一覧上部の案内に「ナビの件数には、あなたが処理できる申請（N件）だけを数えています」と書いた。
   - 開発 DB では、admin のバッジが 3 → 2 になった（ID 11 は admin 自身の申請）。
4. **`config/initializers/sqlite_lock_wait.rb` の安全策**
   - `SqliteLockWait.install` に、次のガードを入れた。
     - Rails 8.0 以上：何もしない。
     - 上書き対象のメソッド `configure_connection` が無い：警告をログに出して何もしない（起動は止めない）。
     - 二重には入れない。
   - テスト `test/initializers/sqlite_lock_wait_test.rb`（5件）
     - ガードの3パターン。
     - 実際に接続を作ったとき、`busy_handler_timeout=` に database.yml の timeout が渡ることを、接続を見張って確認する。

### 仕様に明記の無い点で決めた扱い
- **過去日の休暇申請：可（1年前まで）**
  - 急な病欠を後から「欠勤」や「有給」として届け出るのが一般的なため。
  - 未来も1年先まで。1回の申請は31日まで（長い休暇は分けて申請する）。
- **過去・当日の承認済み休暇への取消申請：不可**
  - 取消申請できるのは、開始日が明日以降の休暇だけ。期間の途中（開始日を過ぎた）の休暇も不可。
  - 休んだ実績を後から変えることになり、F12 の予実比較や F14 の締めと食い違うため。画面では「取り消す必要がある場合は管理者に相談してください」と案内する。
  - 開始日の前に出した取消申請は、処理が遅れて開始日を過ぎても承認・却下できる。承認画面に「開始日を過ぎています。実際に休んだかどうかを確認してから処理してください」と注意を出す。
- **半休の重なり**：同じ日の午前半休と午後半休も「重なり」とし、両方を休むなら「全日」で申請する（フォームにも明記した）。DB の一意制約（同じ人・同じ種類・同じ対象日の承認待ちは1件）とも整合する。
- **土日の扱い**：日数は土日を除いて数える（全種類共通の表示）。有給休暇で土日だけの期間は申請不可。特別休暇・欠勤は土日だけでも申請できる（土曜のシフトなどを想定）。
- **勤怠の記録がある日の休暇**：申請・承認は止めない。承認画面で「この期間に勤務の記録があります」と知らせる。
- **取消後の状態**：休暇申請の状態は「承認済み」のまま、`cancelled_at` で取消済みを表す。バッジは「承認済み」「取消済み」を並べる。
