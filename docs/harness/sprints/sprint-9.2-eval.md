1. **[軽微] 申請できる範囲（今日+1年）より先の日付で、申請画面のプレビューの日数が祝日を数えに入れる**

## 所見
### 特別休暇・欠勤を休日だけで申請できる扱いについて
- **仕様とは矛盾しない。** 仕様が禁じているのは「有給休暇で、期間がすべて休日のもの」だけ。特別休暇・欠勤は、休日だけの期間でも禁じていない。日数を休日を除いて数える規則（0日になる）にも従っている。
- ただし、気になる点が2つある。
  - 休日に「欠勤」するのは、意味として不自然。土曜にシフトがある、という想定なら、F11/F12（シフト）が入ったあとは、シフトのある日だけを認めるのが自然。
  - F14 の月次集計で「欠勤回数」を数えるときに、0日の欠勤を回数に入れるかどうかを決める必要がある。今は承認すると勤怠履歴にバッジが出るので、数え方を F14 で明確にすること。仕様の確認が必要なら、オーケストレーター経由で planner に相談すること。

### gem（`holiday_jp` 0.8.1）と内部 Hash の参照について（コード品質）
- **gem の採用は妥当。**
  - 依存 gem が無く、データは gem に同梱されている（外部 API なし。仕様の「アプリが自動で判定」にも合う）。
  - 振替休日・国民の休日も、データに含まれている（2026/5/6・9/22・2027/3/22 で確かめた）。
  - データが 2050年までという制約は、業務アプリとしては実害が無い。
- **`HolidayJp.holidays.holidays` の直接参照は、許容範囲だが改善の余地がある。**
  - gem の `Holidays` クラスは `attr_accessor :holidays` で Hash を公開している。gem 自身の `holiday?` もこの Hash を使っており、完全な内部実装というわけではない。
  - 参照は `HolidayCalendar.holiday_name` の1か所に閉じている。gem の構造が変わっても、直すのは1行で済む。
  - ただし、この Hash は書き換えができる（`attr_accessor`）。また、gem の公開 API として文書化されているわけではない。gem を更新したときに気付けるよう、次のどちらかをしておくとよい。
    - `holiday_calendar_test.rb` に「`HolidayJp.holiday?` と `HolidayCalendar.holiday?` の結果が一致する」テストを1件足す。
    - `Gemfile` でバージョンを `~> 0.8` などに固定する。
  - なお、`HolidayJp.between` を使わなかった理由（全件を走査する）は妥当。

## 改善点（ジェネレーターへの具体的な指示）
- （バグ 1）`leave_form_controller.js` で、開始日・終了日が祝日データの範囲（`leave_form_holidays` の前後1年）の外にあるときは、日数のプレビューの代わりに「申請できるのは YYYY/MM/DD までです」と出す。範囲の端の日付は `data-` 属性で JS に渡す。または、`end_date` の入力欄に `max` 属性（今日+1年）を付ける。
- （バグ 2・F10 で対応）勤怠履歴で、休暇の期間内の休日の行には、休暇のバッジを出さないか、薄い表示（例：「休日（有給期間中）」）にする。0日の休暇は、月の休暇欄に「特別休暇 0日」のように出すかどうかを決めて、バッジと合わせる。
- （任意）`test/models/holiday_calendar_test.rb` に、`HolidayJp.holiday?(date)` と `HolidayCalendar.holiday?(date)` が一致することを、数日分確かめるテストを足す。gem の内部構造が変わったときに気付けるようにするため。
- （任意）375px の祝日の行でも、日曜と同じく「勤務なし」を出す（チップと並べて折り返さない幅にするか、チップを日付の下に置く）。
